LiveBridge — приложение в строке меню macOS, которое держит наготове голосовую линию GPT-Live через
`codex app-server` на вашем входе в ChatGPT (без API-ключа). Голос работает как ресепшен: болтает,
уточняет, что вы имеете в виду, и передаёт настоящую работу вашей сессии Claude Code через небольшой
мод Claude Code, `livebridge`. Claude делает работу своей моделью, своими инструментами и в своём
режиме разрешений, а голос сообщает вам результат. Держать линию открытой, пока Claude работает, не
нужно: его ответ снова открывает закрытую линию и передаётся голосу, чтобы тот его произнёс. Голос
также следит за тем, что вы набираете в сессии и что отвечает Claude, так что можно переходить от
голоса к клавиатуре и обратно.

*Основной текст — английский ([README.md](../../README.md)); перевод может отставать.*

**Разговор, а не диктовка.** GPT-Live слушает, пока говорит: перебейте его, и он замолчит и выслушает вас; думайте вслух, и он может вставить короткое «угу». **Вы перестаёте платить за тишину:** OpenAI считает голос поминутно, поэтому после 20 секунд тишины линия закрывается и снова открывается, когда вы заговорите, а разговор продолжается с того же места ([Оплата](#бережно-к-оплате)).

<p align="center"><img src="../assets/readme-demo.gif" alt="Разговор с сессией Claude Code через LiveBridge" width="100%"></p>

**Всё локально.** Никакой телеметрии и никакого своего сервера: LiveBridge — мост на вашем Mac
между вашим собственным codex и вашим собственным Claude Code. Приложение и мод общаются через
Unix-сокет, доступный только вашему пользователю, и приложение не слушает ни одного сетевого
порта. Кроме того, что эти два инструмента и так отправляют (голосовая линия в OpenAI через ваш
codex, и только пока она открыта, вместе с тем, что вы набираете в подключённой сессии, и работа Claude в Anthropic через вашу сессию Claude Code),
приложение само выходит в сеть только так: недолго живущий codex, когда вы открываете меню,
запрашивает у OpenAI данные об использовании Codex, в том числе при выключенном звонке, и ради
[обновлений](#обновление): автоматическая проверка в
GitHub, нет ли нового выпуска (раз в день, а также при запуске, пока объявленный им выпуск не
установлен), которую можно выключить; та же проверка, когда вы нажимаете **Check for update**;
`gh auth status`, когда объявлен новый выпуск; и загрузка, её проверка и обновление мода, когда
вы нажимаете **Install**. Что именно уходит в OpenAI, перечислено в разделе
[«Приватность»](#приватность), и там же названы запросы приложения к GitHub; от чего это
защищает, а от чего нет, — в [SECURITY.md](../../SECURITY.md).

> **Неофициальный проект.** Не связан с Anthropic или OpenAI, не одобрен и не поддерживается
> ими. Опирается на экспериментальный realtime API codex, который может измениться с любым
> выпуском codex.

## Быстрый старт

Нужны macOS 14+ на Apple Silicon, Claude Code 2.1.301+ и
[codex](https://github.com/openai/codex) с входом (`codex login`) в план ChatGPT, в Codex которого
входит голос; чтобы собрать приложение самому, ещё Xcode со Swift 6.0+. Подробности — в
разделе [«Требования»](#требования).

```sh
# 1. Мод — из маркетплейса этого репозитория
claude plugin marketplace add getLiveBridge/LiveBridge
claude plugin install livebridge@livebridge

# 2. Приложение — сборка из исходников, установка в /Applications и запуск
git clone https://github.com/getLiveBridge/LiveBridge.git
cd livebridge
scripts/build-app.sh --release
```

3. В сессии Claude Code, с которой хотите говорить, наберите `/live`.
4. Нажмите **Start** в полосе над полем ввода, разрешите доступ к микрофону и говорите.

Не хотите собирать? В каждом [выпуске](https://github.com/getLiveBridge/LiveBridge/releases/latest)
есть приложение образом диска, который собирает и заверяет GitHub Actions; как его проверить и
открыть, сказано в разделе [«Из образа диска»](#из-образа-диска). Мод ставится одинаково в обоих
случаях.

Если в сессии, открытой ещё до установки, команды `/live` нет, откройте сессию заново
([почему](#известные-ограничения)). Обновление, разрешения, сохранение доступа к микрофону между
пересборками и удаление описаны в разделе [«Установка»](#установка).

## Требования

- macOS 14 или новее на Apple Silicon.
- Claude Code 2.1.301 или новее.
- [Codex CLI](https://github.com/openai/codex) (`codex`, проверено с 0.166.0), установленный через
  Homebrew (`brew install --cask codex`) или npm (`npm install -g @openai/codex`), в `PATH`,
  который ваша оболочка задаёт в окне Terminal, с входом через `codex login` в план ChatGPT, в
  Codex которого входит голос (Plus, Pro, Business, Enterprise или Education, по
  [ценам Codex у OpenAI](https://learn.chatgpt.com/docs/pricing)). LiveBridge не запускает codex, чей `codex features list` он не
  может прочитать, поэтому другая версия может не запуститься, пока LiveBridge не обновят.
- Для сборки приложения: Xcode со Swift 6.0 или новее. Проверенные версии перечислены в
  [CONTRIBUTING.md](../../CONTRIBUTING.md#toolchain). Собранное приложение работает на macOS 14 или
  новее.

## Установка

Мод ставится из маркетплейса этого репозитория (команды из [«Быстрого старта»](#быстрый-старт)),
который указывает на тег последнего выпуска, так что вы ставите мод этого выпуска. Приложение в
обоих случаях оказывается в `/Applications`: из образа диска или собранное из исходников. Начиная с первого выпуска после
0.4.2 образ диска подписан Developer ID LiveBridge и нотаризован Apple; 0.4.2 и более ранние
подписаны ad hoc и не нотаризованы, а сборка из исходников не подписана Developer ID и не
нотаризована.

### Из образа диска

1. Скачайте
   [LiveBridge.dmg](https://github.com/getLiveBridge/LiveBridge/releases/latest/download/LiveBridge.dmg)
   из последнего выпуска.
2. Проверьте его с помощью [GitHub CLI](https://cli.github.com) в папке, куда сохранили файл:

   ```sh
   gh attestation verify LiveBridge.dmg --repo getLiveBridge/LiveBridge \
     --signer-workflow getLiveBridge/LiveBridge/.github/workflows/release.yml \
     --source-ref refs/tags/vX.Y.Z --deny-self-hosted-runners
   ```

   где `vX.Y.Z` — тег выпуска, как он назван на его странице. Проверка проходит, только если
   образ собран [рабочим процессом выпуска](../../.github/workflows/release.yml) этого репозитория из
   этого тега на runner'е, который предоставляет GitHub, и с тех пор не изменился. На выпуске после 0.4.2
   подпись Developer ID, которую macOS проверяет сама, говорит, кто подписал образ, а эта проверка
   говорит, из чего он собран; на 0.4.2 и более ранних, чья подпись ad hoc никого не называет, эта
   проверка — единственное свидетельство происхождения образа. Того, что кто-то проверил код, это не доказывает.
3. Откройте образ и перетащите LiveBridge в Applications.
4. При первом запуске выпуск после 0.4.2 заставляет macOS спросить, открывать ли приложение,
   загруженное из интернета; нажмите **Open**. 0.4.2 и более ранние заблокированы, пока вы не
   разрешите их в Системных настройках > Конфиденциальность и безопасность > **Open Anyway**.

### Через Homebrew

```sh
brew install --cask getlivebridge/tap/livebridge
```

Команда ставит тот же образ диска из [собственного tap LiveBridge](https://github.com/getLiveBridge/homebrew-tap): это не официальный cask
Homebrew. Homebrew может сначала попросить доверять этому tap, а macOS спросит при первом запуске, как
описано выше. Дальше приложение обновляется само.

### Из исходников

`scripts/build-app.sh --release` собирает приложение, устанавливает его в `/Applications` (у
вашей учётной записи должно быть право записи туда, как у администратора) и запускает. Чтобы
пересобрать, запустите команду снова. Сборка подписана ad hoc, поэтому после каждой пересборки
macOS снова спрашивает доступ к микрофону. Чтобы разрешение сохранялось, один раз запустите
`scripts/build-app.sh --make-signing-identity`: скрипт сначала спросит, затем создаст
самоподписанный сертификат для подписи кода в вашей связке ключей входа, и следующие
release-сборки будут подписаны им.

Маркетплейс закрепляет мод за тегом последнего выпуска, поэтому приложение, собранное из
основной ветки, работает с модом этого выпуска. Чтобы они совпадали, соберите тег выпуска
(`git checkout vX.Y.Z`) или загрузите мод из рабочей копии командой
`claude --plugin-dir plugin`.

Сборка из исходников сама проверяет обновления, только если вы включите это в Settings.
Установка обновления заменяет её образом выпуска, который подписан Developer ID
LiveBridge, а не вашим самоподписанным сертификатом, поэтому macOS ещё раз спросит доступ к
микрофону; **Install** говорит об этом и сначала спрашивает.

### Обновление

LiveBridge обновляет себя и свой мод, когда вы нажимаете **Install**, и никогда сам по себе.
Обновляется только копия в `/Applications/LiveBridge.app`; любая другая копия говорит об этом в
Settings.

- **Check for updates automatically** в Settings (по умолчанию включено, для сборки из
  исходников выключено): раз в день приложение спрашивает у GitHub, какой выпуск последний. О
  более новом оно сообщает один раз, уведомлением, чья кнопка **Install** его устанавливает, а
  меню в строке меню предлагает **Install LiveBridge X.Y.Z…**, пока он не установлен, и ради
  этого пункта снова спрашивает GitHub при каждом запуске. **Check for update** в Settings
  спрашивает сразу.
- Для **Install** нужен [GitHub CLI](https://cli.github.com) с выполненным входом
  (`gh auth login`); без него Install ничего не скачивает и даёт ссылку на страницу выпуска. Он
  скачивает образ выпуска, проверяет его той же командой `gh attestation verify`, что и выше,
  затем проверяет приложение внутри и ничего не устанавливает, если не прошла хоть одна
  проверка. Он ждёт, пока Claude ещё занят голосовым запросом, обновляет мод командами
  `claude plugin marketplace update livebridge` и `claude plugin update livebridge@livebridge`,
  останавливает звонок, ставит новое приложение на место за один шаг и открывает его.
- После этого Settings показывает, с какой версии прошло обновление. Если мод обновить не
  удалось, там будут эти две команды, чтобы вы выполнили их сами. Сессии Claude Code, открытые
  раньше, работают со старым модом, пока их не перезапустить; Settings перечисляет подключённые
  сессии, которые ещё на нём.
- Загрузка обновления не ставит атрибут карантина, поэтому macOS не должна останавливать первый
  запуск обновлённого приложения вопросом, как после первой загрузки; это следует из кода и пока
  не проверено на деле. Вместо этого работают проверки выше
  ([SECURITY.md](../../SECURITY.md#what-an-update-installs)). Выпуски после 0.4.2 подписаны
  Developer ID LiveBridge, поэтому разрешение на микрофон должно переходить от одного выпуска к
  следующему; это следует из того, как macOS привязывает разрешение, и пока не проверено на деле.
  0.4.2 и более ранние подписаны ad hoc, так что первое обновление с одного из них
  ещё раз спрашивает микрофон, при первом **Start**.

Чтобы обновиться вручную, наберите `/live off` во всех сессиях (мод снова открывает приложение
из `/Applications`, как только оно перестаёт отвечать), закройте LiveBridge, установите образ
нового выпуска, как описано выше, и выполните две команды `claude plugin`.

### Разрешения

Первый Start спрашивает у macOS доступ к микрофону. Если доступ запрещён, звонок останавливается
с фразой, а кнопка **Open Microphone Settings** в меню LiveBridge в строке меню открывает
«Конфиденциальность и безопасность» > «Микрофон», где нужно разрешить LiveBridge. macOS
спрашивает снова при первом Start после первого обновления с выпуска, подписанного ad hoc, и
после каждой пересборки из исходников, подписанной ad hoc (см. выше).
macOS может также спросить, можно ли LiveBridge находить устройства в локальной сети. Голосовой
линии нужно и это второе разрешение; без него звонок остановится с фразой, где его включить.

### Удаление

Из клона репозитория `scripts/build-app.sh --uninstall` удаляет `/Applications/LiveBridge.app`,
как бы оно ни было установлено, его объект входа и все файлы, которые оно хранит, и печатает две
команды, которые оставляет вам: `tccutil reset Microphone com.getlivebridge.livebridge` и
`claude plugin uninstall livebridge@livebridge`.

Без клона выключите **Open at login** в Settings приложения LiveBridge, закройте LiveBridge и
выполните те же шаги в Terminal:

```sh
rm -rf /Applications/LiveBridge.app ~/Library/Application\ Support/LiveBridge \
  ~/Library/{Caches,WebKit}/com.getlivebridge.livebridge \
  ~/Library/HTTPStorages/com.getlivebridge.livebridge{,.binarycookies} \
  ~/Library/Preferences/com.getlivebridge.livebridge.plist
tccutil reset Microphone com.getlivebridge.livebridge
claude plugin uninstall livebridge@livebridge
```

Ни то ни другое не удаляет копию с именем `/Applications/.LiveBridge-update-….app`, которую
может оставить обновление, прерванное посреди установки. Приложение удаляет такие копии при
следующем запуске; после удаления приложения удалите её вручную, если она есть.

`claude plugin uninstall` может оставить снимок мода, `~/.claude/plugins/store/livebridge_*.json`: в
документации Claude Code о том, что удаляется, этого файла нет, а проверка не запускалась. Если он
есть, удалите его вручную.

## Использование

### Команды

В сессии Claude Code, с которой хотите говорить:

| Команда | Что делает |
|---|---|
| `/live` | Подключает сессию к LiveBridge под её заголовком и открывает приложение, если оно не запущено. В уже подключённой сессии возвращает полосу и отвечает одной строкой: звонок, цель, непрослушанные результаты, минуты за сегодня. |
| `/live off` | Отключает сессию от LiveBridge. |

Команда называется `/live`, а не `/voice`, потому что `/voice` — собственный голосовой режим
Claude Code. Держать ли набранное в сессии вне голоса, пока звонок остановлен, решает не
команда, а одна настройка для всех сессий в окне [Settings](#настройки) приложения LiveBridge.

### Полоса и меню

Нажмите **Start** — в полосе над полем ввода или в меню LiveBridge в строке меню — и говорите.

- **Start в полосе** делает её сессию целью и начинает звонок; открытая им линия получает разговор
  сессии, а сводку загружает и тогда, когда голосу не хватало бы части сессии (см. **Load context**
  ниже), но при включённой **Pause sync** и после паузы только если сводки ещё нет
  ([подробности](../../docs/architecture/overview.md#components)). Пока звонок идёт с другой сессией,
  полоса показывает **Talk here**. Если в подключённой сессии полосы нет, `/live` возвращает её.
- **Меню в строке меню** показывает звонок, подключённые сессии (щелчок делает сессию целью),
  **Load context**, **Conversation** — разговор цели в том виде, в каком его хранит LiveBridge
  (со строкой **Task** на каждый запрос, который голос передал Claude, и строкой **Loaded context** там, где была загружена сводка),
  лимиты использования, минуты, **Star LiveBridge on GitHub** (открывает страницу репозитория), **Settings…** и
  **Quit LiveBridge**. Во время звонка **Conversation** показывает ваши слова и слова голоса по мере
  того, как их расшифровывает codex, поэтому ваши могут появиться чуть позже, чем вы их сказали, а
  слова голоса чуть раньше, чем вы их услышите. Когда реплика закончена, её заменяет окончательный
  текст. Хранится только окончательный текст: слова, которые его не дождались к закрытию линии,
  пропадают.
- **Mute** (рядом со **Stop**, в полосе и в карточке звонка в меню; **Unmute**, пока микрофон
  выключен) освобождает ваш микрофон, пока звонок продолжается: ответ Claude по-прежнему открывает
  линию и передаётся голосу, чтобы тот его произнёс. Полоса сохраняет фазу и добавляет `· muted`;
  меню пишет «Muted — line closed», пока линия не открыта. Mute не закрывает линию: открытая линия
  закрывается после обычной тишины, отсчитываемой от Mute, если вы говорили, и тогда же, когда
  закрылась бы без Mute, если линия уже молчала; она оплачивается как любая тишина, так что Mute не
  экономит минуты realtime. **Unmute** снова берёт микрофон, и если не получается (доступ запрещён,
  занят, отсутствует), звонок завершается с указанием причины. **Stop** завершает звонок и Mute;
  следующий **Start** начинается с включённым микрофоном. Mute — не замок: любой процесс, запущенный
  от вашего имени, может его снять ([SECURITY.md](../../SECURITY.md#who-can-drive-the-bridge)).
- **Load context** доступен, только когда голосу не хватает части цели: сводки нет, и **Pause sync** не даёт следующей линии её загрузить, ход не дошёл,
  вопрос или уведомление о разрешении не дошли до приложения, ходы шли при выключенном моде, строк
  после сводки больше, чем голос может принять (длинный разговор это превышает), сессия была
  приостановлена и у неё есть сводка, или её мод не синхронизируется. Иначе пункт называется **Context up to date** и
  недоступен, потому что голос уже знает разговор. Если линия не открыта, следующая загрузит сводку и больше ничего не потеряно, он называется
  **Context loads with the line** и недоступен, потому что следующая линия запросит её сама. У сводки нет даты, поэтому она может быть
  проигнорирована, а пункт останется доступным ([BR-002](../../docs/bugs/BR-002.md)).
- **New conversation…** стирает разговор цели и её загруженный контекст, а × у сессии убирает её и
  стирает её разговор; оба пункта сначала спрашивают. Голос начинает заново со следующего открытия
  линии. Результаты, которые он ещё не произнёс, остаются и добавляются снова; их очищает только
  **Stop**. Для ждущих вопросов Claude правила другие
  ([подробности](../../SECURITY.md#residual-risk-by-design)). Если включена **Load a session's context on its first call** или **Pause sync** выключена и сессия не
  приостановлена, следующая линия сама загружает сводку той же стенограммы сессии, а в ней есть и
  то, что сессия прочитала; чтобы этого избежать, сначала выполните `/clear` в сессии, затем нажмите
  **New conversation**. `/live` в убранной сессии снова её подключает.

### Настройки

**Settings…** открывает окно настроек LiveBridge:

- **Voice**: один из голосов realtime, которые предлагает ваш codex (codex перечисляет их, когда
  окно открывается), или **Codex default**. Звучит со следующего открытия линии.
- **Prompt** (по умолчанию пусто): ваши собственные указания голосу, например «Speak with me in
  Spanish», до 2 000 символов. Они добавляются после собственных правил LiveBridge для голоса,
  которые важнее, если они расходятся, и действуют со следующего открытия линии.
- **Pause sync while the call is stopped** (по умолчанию выключено): по умолчанию то, что вы
  набираете в подключённой сессии, и итоговый ответ Claude на это попадают в разговор этой сессии с
  голосом, даже пока звонок остановлен, и голос знает их, когда откроется следующая линия. С Mac
  ничего не уходит, пока не откроется линия. Если текст не должен попасть в OpenAI, включите
  настройку, выключите следующую, если сводки у сессии может ещё не быть, нажмите Stop и только потом печатайте: ничего из набранного при остановленном звонке не
  записывается, а сессия помечается как приостановленная. Пока настройка включена, ни одна линия
  сама не загружает сводку, как и после паузы, кроме сессии без сводки (следующая настройка);
  в остальных случаях это делает только **Load context**. Такая сводка пишется по всей стенограмме и несёт то, что вы приостановили. Набранное в
  ходе, который выполняет голосовой запрос, проваливает его ответ: в нём ничего не записывается и не
  произносится. Настройка не удаляет уже записанное, а более поздние ответы Claude могут повторять
  приостановленный текст; что она делает и чего не делает, сказано в
  [SECURITY.md](../../SECURITY.md#residual-risk-by-design).
- **Load a session's context on its first call** (по умолчанию включено; выключено, если при обновлении была включена **Pause sync**):
  линия, открытая для сессии, сводки которой у голоса нет, запрашивает её, даже если включена
  **Pause sync** или сессия приостановлена, в том числе для старого чата и после **New
  conversation**. Такая сводка пишется по всей стенограмме, поэтому несёт то, что вы приостановили,
  и уходит в OpenAI. Когда у сессии есть сводка, то, что идёт дальше, определяет пауза. Если
  настройка выключена, под паузой сводку загружает только **Load context**.
- **Play sounds for requests and answers** (по умолчанию включено): короткий звук на каждый запрос,
  который голос передаёт Claude ([почему](#известные-ограничения)), и на каждый ответ, ошибку или
  вопрос Claude, пришедшие на открытую или открывающуюся линию, когда никто не говорит. Сигнал
  ждущего результата звучит в любом случае.
- **Notify when a result is waiting** (по умолчанию включено): вместе с сигналом о результате,
  который ждёт, пока линия закрыта, уведомление macOS называет сессию («Alpha has a new result —
  speak to hear it»), но никогда не сам результат. Щелчок по нему открывает меню LiveBridge.
- **Open at login** (по умолчанию выключено).
- **Updates**: текущая версия, **Check for update**, **Check for updates automatically** и что
  сделало последнее обновление ([«Обновление»](#обновление)).

### Что делает голос

- Сам отвечает на светскую беседу и объяснения и передаёт всё, чему нужны репозиторий или
  сессия: задачи, вопросы о коде, решения, исправления и остановки.
- Прежде чем передать что-то разрушительное или внешнее (удалить, запушить, опубликовать,
  отправить, задеплоить, оплатить), повторяет запрос и спрашивает «да?». Это привычка, которую
  голосу велено соблюдать, а не защита; что защищает, сказано в [SECURITY.md](../../SECURITY.md).
- Пересказывает результаты одной-двумя фразами с названием сессии. Блоки кода и таблицы
  остаются в сессии, а распознанные учётные данные скрываются.
- Возвращается, когда Claude закончил. Держать линию открытой не нужно: она закрывается, когда
  разговор стихает, а ответ Claude на ваш запрос снова открывает её и передаётся голосу, чтобы тот
  его произнёс, так что пока Claude работает, можно отойти. Это касается сессии, с которой вы
  говорите; результат из другой сессии звучит сигналом и ждёт ([как это
  оплачивается](#бережно-к-оплате)). Если на снова открытой линии голос молчит, ответ тоже звучит
  сигналом и ждёт, так что он не теряется. Вопрос, который Claude вам задаёт, или запрос разрешения,
  которого он ждёт, открывает линию так же, но голос может его не произнести: не полагайтесь на это,
  когда вас нет у Mac ([известные ограничения](#известные-ограничения)).
- Когда Claude задаёт вопрос, он передаётся голосу, чтобы тот задал его вам, а ваш ответ уходит
  обратно в ту же сессию. Так же и с вопросом, который Claude задаёт по ходу работы (окно с
  вариантами): голос получает его, чтобы рассказать о нём, объяснить варианты своими словами и
  обсудить их с вами сколько угодно, не обращаясь к Claude. Ваше решение, вариант или встречный
  вопрос к Claude, становится ответом в окне; ответить с клавиатуры по-прежнему можно. Работа,
  которую Claude заканчивает позже в фоне, передаётся голосу как обновление.
- Когда Claude ждёт ответа на запрос разрешения, голос получает уведомление и может сказать об этом,
  кроме случая, [когда Claude Code управляет организация](#известные-ограничения). На запрос вы
  отвечаете в Claude Code; LiveBridge никогда не отвечает за вас.
- Получает то, что вы набираете. Пока сессия подключена, то, что вы в ней набираете, и итоговый
  ответ Claude на каждый ход, не бывший голосовым запросом, попадают в разговор этой сессии с
  голосом как контекст: сигнала для них нет, и закрытую линию они не открывают
  ([ограничения](#известные-ограничения)). Открытая линия получает их сразу, а линия, открытая
  позже, начинается с них. Голосовой ответ, вытесненный более новым запросом, не произносится, но
  сохраняется и добавляется так же. Текст Claude посреди хода не синхронизируется, кроме того, что
  он написал прямо перед вопросом или запросом разрешения: это идёт вместе с ним; субагенты и вывод
  инструментов не синхронизируются. Вопрос или запрос разрешения в цели передаётся голосу, какой бы
  ход его ни вызвал; в другой сессии он идёт, как шёл бы результат оттуда, а если ход не был
  голосовым запросом, только записывается. У хода, который пауза не пустила, ничего этого нет. Когда
  вопрос или запрос разрешения решён без голоса или ход закончился без ответа, голосу передаётся
  строка об этом ([какие строки](../../SECURITY.md#what-session-text-can-do)).

## Бережно к оплате

Realtime-сессия голоса стоит денег, пока открыта, поэтому LiveBridge открывает её, только пока
кто-то говорит, пока может прийти ответ Claude на ваш только что переданный запрос, или чтобы
произнести этот ответ, вопрос Claude или то, что Claude ждёт вашего разрешения:

- Пока звонок включён и никто не говорит, микрофон питает только детектор голоса на вашем Mac.
  Звук никуда не отправляется.
  Пока Mute включён, LiveBridge не держит микрофон, и индикатор микрофона macOS это показывает.
- Когда вы начинаете говорить, линия открывается. Две секунды до начала речи сохраняются и
  отправляются первыми, так что первые слова не теряются.
- Линия закрывается после 20 секунд тишины. Звук без слов (музыка, телевизор) закрывает её
  через 90 секунд.
- Когда голос передаёт запрос Claude (handoff), линия остаётся открытой до 2 минут после этой
  передачи и оплачивается как любая открытая линия, а ответ Claude передаётся голосу, чтобы тот его
  произнёс, как только никто не говорит. Следующая передача начинает эти 2 минуты заново; разговор,
  который ничего не отправляет Claude, закрывается после обычных 20 секунд тишины.
- Ответ Claude на запрос, переданный сессии, с которой вы сейчас говорите, вопрос Claude в ней или
  запрос разрешения, которого он ждёт, пришедший после закрытия линии, снова открывает линию и
  передаётся голосу, чтобы тот его произнёс; это оплачивается как любая открытая линия. Всё
  остальное, что приходит при закрытой линии (всё из сессии, с которой вы переключились, позднее
  обновление), звучит сигналом и ждёт: полоса и меню показывают его как непрослушанное, и оно
  передаётся голосу, когда вы заговорите снова ([когда он считается
  услышанным](../../docs/architecture/overview.md#a-result-while-the-line-is-closed)).
- У каждой сессии Claude Code свой разговор с голосом. Он переносится в следующую
  realtime-сессию, а также через Stop и Start, поэтому голос помнит, что вы сказали минуту назад.
  Новая цель переключает разговор: открытая линия закрывается, и ваши следующие слова открывают
  её с разговором новой цели.
- Меню показывает минуты открытой линии, которые приложение считает с момента подключения голоса,
  так что ваш план может насчитать немного больше. OpenAI оценивает голос на компьютере поминутно из
  бюджета использования Codex, а в её API то же семейство моделей тарифицирует и тишину
  ([подробности](../../docs/research/2026-11-04-gpt-live-billing.md),
  [лимиты](../../docs/research/2026-11-05-gpt-live-limits.md)); последнее слово за страницей использования
  вашего плана.
- Меню показывает, какая доля вашего расхода Codex и Claude использована: по строке на каждый, в
  процентах по каждому окну, которое сообщает план (до трёх в строке, например
  `7% of 5 h · 19% of week`), оранжевым от 90 %; при наведении на строку видно, когда окна
  сбрасываются. Данные Codex читаются при каждом открытии меню, не чаще раза в минуту, недолго
  живущим codex; данные Claude приходят из подключённой сессии, когда она уже ответила. Строка,
  которой нечего показать, не выводится, а строка Codex говорит `blocked`, когда codex сообщает,
  что обычное использование не разрешено. Последнее показание Codex видно сразу, а через несколько
  секунд его сменяет новое, так что цифры могут измениться при открытом меню; сразу после запуска
  строка появляется, когда придёт первое показание, а если чтение не удаётся, показание исчезает
  через 15 минут.
  Какой лимит остановит голос первым, не документировано
  ([подробности](../../docs/research/2026-11-05-gpt-live-limits.md)).

## Приватность

У LiveBridge нет телеметрии, и он не слушает ни одного сетевого порта; мод общается с
приложением через Unix-сокет в папке, которую может открыть только ваш пользователь. Что уходит
в OpenAI через realtime-сессию codex:

- звук микрофона, пока линия открыта: от двух секунд до начала вашей речи (или, для линии, которую
  открыл ответ, вопрос или запрос разрешения Claude, с момента её открытия) до закрытия линии (при
  Mute LiveBridge ничего не захватывает, поэтому звук не уходит; сказанное до нажатия Mute на линии,
  которая уже подключалась, всё же может уйти);
- инструкции голоса: собственные правила LiveBridge, а затем ваш **Prompt** из Settings, если
  вы его написали;
- недавний разговор сессии-цели (до 64 последних реплик и не больше, чем принимает codex: 128
  элементов и около 8192 токенов вместе с контекстом и открытыми задачами), чтобы продолжить его в
  новой realtime-сессии. В нём то, что вы набрали в этой сессии, и итоговый ответ Claude на каждый
  ход, не бывший голосовым запросом, чем бы он ни был начат (вы его набрали, расписание, другой
  агент, фоновая задача), а также заметки мода, ваша речь и речь голоса, поэтому набранное в сессии
  уходит в OpenAI, когда открывается линия с этой сессией. Пока линия открыта, каждая новая реплика
  цели попадает в неё сразу. Синхронизированные реплики другой сессии уходят, только когда линия
  открывается с ней как с целью; её результаты, вопросы и уведомления о разрешении попадают в
  открытую линию, чья бы это сессия ни была;
- запросы сессии-цели, которые ещё не закрыты, в виде их однострочных описаний;
- каждый результат, вопрос, обновление, уведомление о разрешении, набранный текст, ответ на ход, не
  бывший голосовым запросом, голосовой ответ, вытесненный более новым запросом, и заметка мода —
  одной строкой не длиннее 2000 символов, без блоков кода и таблиц (набранный текст, который состоит
  только из кода или таблицы, заменяется фразой о том, что набран код). Заметки мода называют
  инструмент разрешённого или решённого запроса разрешения и сообщают, что вопрос закрыт или что ход
  закончился без ответа. Вопрос, который Claude задаёт посреди хода, и уведомление о разрешении,
  которое запросил основной цикл Claude (не субагент), несут и то, что Claude написал прямо перед
  ними. Обновление — это ответ Claude в следующем ходе, начатом уведомлением фоновой задачи, в
  течение 10 минут после голосового запроса и пока в сессии не начался любой другой ход;
- сводка контекста сессии-цели — одной строкой не длиннее 1500 символов. Она сохраняется при
  загрузке и отправляется при каждом открытии линии, пока эта сессия — цель, в том числе после
  Stop и Start и перезапуска приложения. Подменю Conversation показывает эту строку ровно в том
  виде, в каком она отправляется;
- с каждой строкой выше — метка её сессии: название сессии Claude Code (до 80 символов) или, если
  его нет, имя папки сессии. В метке ничего не скрывается, и пауза её не касается, так что название,
  написанное из приостановленного текста, уходит с каждой строкой;
- WebRTC-предложение, в котором локальные сетевые адреса Mac указаны как кандидаты для
  соединения.

Результаты, вопросы, обновления, сводки и строки набранных ходов сначала проходят через фильтр,
который скрывает известные виды учётных данных (закрытые ключи, JWT, распространённые API-токены,
пароли в URL, поля вроде `password=`). Это список шаблонов, а не гарантия: всё остальное, что вы
набираете, уходит как набрано.

Тред codex, который несёт голос, эфемерный и только для чтения; в нём выключены все функции
codex, кроме хранения входа и работы через прокси, и все MCP-серверы; он нужен только для
разговора. Работа Claude уходит в Anthropic, как и всегда в вашей сессии Claude Code.

Когда вы открываете меню, LiveBridge запускает недолго живущий codex, и тот спрашивает у OpenAI
под вашим входом в ChatGPT, сколько вашего лимита Codex использовано (процент и время сброса
каждого окна). Это не чаще раза в минуту и происходит также при выключенном звонке; звук и текст
при этом не отправляются. Данные Claude приходят в приложение от мода через сокет и никуда дальше
не идут; оба набора приложение хранит только в памяти.

Ради обновлений приложение обращается к GitHub. Если включено **Check for updates
automatically**, раз в день (и при каждом запуске, пока объявленный им выпуск не установлен) оно
без учётных данных спрашивает у API GitHub, какой выпуск последний; GitHub видит IP-адрес вашего
Mac. **Check for update** в Settings отправляет тот же запрос, когда вы его нажимаете. Когда
автоматическая проверка находит более новый выпуск, приложение запускает `gh auth status`, чтобы
сказать, можно ли проверить образ. Только когда вы нажимаете **Install**, оно скачивает образ и
запускает `gh attestation verify` и `claude plugin`, которые обращаются к GitHub, а `gh` ещё и к
Sigstore за корнем доверия, под вашими собственными входами. Каждый запрос перечислен в
[SECURITY.md](../../SECURITY.md#what-leaves-the-mac).

На вашем Mac приложение хранит свои настройки, счётчик использования, время последней проверки
обновлений и версии, о которых оно сообщило, что сделало последнее обновление, а также для
каждой из 20 последних использованных сессий её недавний разговор (до 64 реплик, в том числе
набранное вами в ней; записывается без звонка, если не включена **Pause sync**) и последнюю
загруженную из неё строку контекста, в `~/Library/Application Support/LiveBridge`, в папке, которую может открыть только ваш
пользователь ([как она хранится](../../SECURITY.md#residual-risk-by-design)). Реплики сессии стираются, когда
вы нажимаете **New conversation**, пока она цель, или убираете её через ×. Отключившаяся сессия
хранит их, пока их не вытеснят 20 сессий, использованных позже; чтобы стереть их раньше, снова
наберите в ней `/live` и нажмите **New conversation**. Удаление приложения стирает всё. Мод держит собственный снимок в хранилище плагинов Claude Code ([что в нём](../../SECURITY.md#residual-risk-by-design)).

В [SECURITY.md](../../SECURITY.md) — модель угроз; коротко: всё, что слышит ваш микрофон, может стать
запросом, который Claude выполнит в режиме разрешений самой сессии.

## Известные ограничения

- Голос иногда говорит, что смотрит («On it», «Looking now»), но не передаёт запрос, и до Claude
  ничего не доходит: примерно один запрос из пяти с правилом в его первой редакции и 0 из 20 с
  нынешним правилом, слишком мало, чтобы отличить от везения ([BR-001](../../docs/bugs/BR-001.md)). Голос
  может и заявить о работе, которой не делал, как в «I'll take a look.», в том числе по репликам,
  которые есть у него только как контекст ([ADR 0001 (n), (o)](../../docs/adr/0001-platform-findings.md)).
  Приложение играет короткий звук, когда ставит запрос в очередь для Claude, и это не тот звук,
  что у ответа; если голос говорит, что смотрит, а этого звука нет, повторите запрос. По словам приложение не может отличить такое обещание от
  ответа: голос говорит на вашем языке.
- Вопрос Claude или запрос разрешения, которого он ждёт, только передаётся голосу, и голос может его
  не произнести; ничто его не заставляет. Поэтому не полагайтесь на то, что голос объявит запрос
  разрешения, когда вас нет у Mac: Claude может ждать без всякого объявления. Запрос разрешения
  по-прежнему ждёт в Claude Code, и это единственный контроль; голос контролем не является, а
  LiveBridge на него никогда не отвечает. В проверках уведомление о разрешении из набранного хода на
  открытой линии было произнесено до ответа с клавиатуры в 0 из 3 запусков, это подсчёт, а не доля
  ([ADR 0001 (n)](../../docs/adr/0001-platform-findings.md)). Закрытая линия открывается ради них, только
  если в разговоре цели есть ваш ход; иначе приложение подаёт сигнал, а при выключенном звонке они
  только записываются.
- Что приложение Claude для компьютера сообщает как источник набранного текста, не наблюдалось ([ADR
  0001 (m)](../../docs/adr/0001-platform-findings.md)). Мод записывает набранное как ваше, только если его
  источник `composer`. Если текст, набранный там, придёт с другим источником, ничего набранного там
  не запишется, пропуск не отметится, меню скажет **Context up to date**, а пауза будет слабее
  ([подробности](../../SECURITY.md#what-session-text-can-do)).
- Результат, пришедший, пока линия его ждёт, передаётся голосу как текст, который нужно произнести;
  у codex нет вызова, который заставил бы голос заговорить сразу, поэтому когда сказать, решает
  модель. В проверке голос произнёс его через несколько секунд. Если нет, результат остаётся
  непрослушанным: он снова передаётся голосу с вашими следующими словами, или прозвучит сигналом,
  когда линия закроется.
- Когда ответ Claude снова открывает линию, голос может промолчать: так было в 4 из 14 замеренных
  запусков, выборка маленькая ([ADR 0001 (n)](../../docs/adr/0001-platform-findings.md)). Тогда линия
  закрывается через 5 секунд после подключения, а ответ звучит сигналом и ждёт, как описано ниже.
  Когда голос заговаривал, он начинал примерно в пределах 2 секунд после подключения; голос, который
  начал бы позже этих 5 секунд, обрывается.
- Когда ваши следующие слова снова открывают линию, голос иногда отвечает только на них и не
  произносит ждущий результат. Результат не теряется: он продолжает ждать, звучит сигналом и
  приходит уведомлением, когда линия закрывается, и снова передаётся голосу, когда линия
  откроется в следующий раз.
- На лимите использования вашего плана ChatGPT голос останавливается, пока лимит не сбросится. Меню
  и полоса говорят об этом фразой codex с временем сброса, если codex его называет, а звонок
  завершается, чтобы речь не открывала линии, которые дают сбой. Claude Code продолжает работать,
  ответы продолжают ждать, а Start пробует ещё раз. Лимит приложение узнаёт только по формулировке
  codex или коду ошибки сервиса: больше о нём ничего не сообщает
  ([подробности](../../docs/research/2026-11-05-gpt-live-limits.md)). Отказ, который оно не узнаёт,
  например линия, оборвавшаяся без объяснения причин («The voice session closed (transport_closed).
  »), оставляет звонок включённым, и ваши следующие слова пробуют снова; нажмите **Stop** до сброса
  лимита.
- Промпт, набранный не в композере (сообщение хоста, расписание, другой агент и, видимо, Remote
  Control), не записывается в разговор голоса как ваши слова, хотя ответ Claude на него
  записывается, и под паузой не отклоняет идущий ход
  ([SECURITY.md](../../SECURITY.md#what-session-text-can-do) говорит, какие промпты считаются вашими).
- Сессия, оставшаяся на моде из версий до этой, пока не перезапустится, не синхронизируется: она
  загружает сводку, как сессия с пропущенными ходами, и никакая пауза не отклоняет её реплики ([что
  ещё отличается](../../CHANGELOG.md)).
- В сессии Claude Code, которая была открыта ещё до загрузки мода, `/live` может заработать
  только после того, как сессию откроют заново.
- В приложении Claude для компьютера `/live`, набранная в сессии, процесс Claude Code которой ещё
  не запущен (новая сессия или только что открытая заново), может показать «/live isn't a command
  here.» Команда всё равно выполняется. Приложение берёт список команд такой сессии из проверки,
  которую запускает с выключенными хуками, поэтому код мода, объявляющий `/live`, там не
  работает; когда сессия запущена, приложение берёт список у неё самой. Со стороны мода это не
  исправить: статический файл команды попал бы в список как `/livebridge:live`, а не `/live`, и
  с выключенными хуками отправил бы свой текст модели вместо того, чтобы запустить мод.
- Произнёс ли ответ ждущий результат, определяется по его словам и списку частых слов только
  английского и русского языков
  ([правило](../../docs/architecture/overview.md#a-result-while-the-line-is-closed)). На другом языке
  результат может засчитаться услышанным, когда голос лишь упомянул его.
- Там, где Claude Code управляет организация, ничто в LiveBridge не сообщит вам, что ждёт запрос
  разрешения. Встроенная защита Claude Code загружается на компьютере с управляемыми настройками и
  в сессии, где выполнен вход с планом Team или Enterprise, и там хуки разрешений мода не
  выполняются. Запрос по-прежнему появляется в Claude Code и ждёт вас, но голос о нём ничего не
  говорит, а строка меню показывает, что Claude работает, поэтому загляните в Claude Code, если
  ответ задерживается. `/plugin` называет эти хуки, а свежие версии Claude Code ещё и выводят
  строку о том, что хук пропущен. Вопросы Claude по-прежнему доходят до голоса. Хуки
  [измерены](../../docs/adr/0001-platform-findings.md) в контейнере Linux; то, что делают голос и строка
  меню, следует из кода, настоящую линию не запускали. Случай Team и Enterprise описан по
  документации Claude Code.
- С `allowManagedHooksOnly`, `allowManagedModsOnly` или `disableAllHooks` в управляемых настройках
  мод не загружается и `/live` не работает. Администратор может [установить мод как собственный
  мод
  организации](https://code.claude.com/docs/en/plugins/mods/admin#install-your-organizations-mods)
  из папки на каждом компьютере: тогда хуки разрешений выполняются, в том числе с первыми двумя
  настройками ([измерено](../../docs/adr/0001-platform-findings.md)). По документации Claude Code,
  включить копию из маркетплейса в управляемых настройках недостаточно.

## Планы и где нужна помощь

Сегодня LiveBridge — это одно приложение для Mac, один исполнитель (Claude Code) и один
поставщик голоса (codex на входе в ChatGPT). Три части стыкуются через узкие швы, и каждое из
направлений ниже открыто для участников. Задачи по ним помечены меткой
[help wanted](https://github.com/getLiveBridge/LiveBridge/issues?q=is%3Aissue+is%3Aopen+label%3A%22help+wanted%22);
с каких файлов начать, сказано в [CONTRIBUTING.md](../../CONTRIBUTING.md#where-to-start).

- **Windows и Linux.** Приложение в строке меню, его аудиостраница и сервер сокета привязаны к
  macOS; протокол между модом и приложением и сам мод переносимы. Перенос начинается с
  приложения для новой платформы, которое говорит по тому же протоколу.
- **Другие агенты-исполнители**, например Codex CLI, Hermes Agent или Gemini CLI: каждому нужен
  свой адаптер, который говорит по тому же протоколу, что и мод Claude Code.
- **Другие поставщики голоса**, например OpenAI Realtime API с вашим собственным API-ключом или
  Gemini Live API от Google: каждый стал бы ещё одной реализацией realtime-протокола приложения.
