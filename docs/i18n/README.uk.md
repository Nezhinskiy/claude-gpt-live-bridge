LiveBridge — це застосунок у рядку меню macOS, який тримає напоготові голосову лінію GPT-Live через
`codex app-server` на вашому вході в ChatGPT (без API-ключа). Голос працює як ресепшн: розмовляє,
перепитує, що ви маєте на увазі, і передає справжню роботу вашій сесії Claude Code через невеликий
мод Claude Code, `livebridge`. Claude виконує роботу власною моделлю, власними інструментами та у
власному режимі дозволів, а голос повідомляє вам результат. Тримати лінію відкритою, поки Claude
працює, не потрібно: його відповідь знову відкриває закриту лінію й передається голосу, щоб той її
вимовив. Голос також стежить за тим, що ви набираєте в сесії та що відповідає Claude, тож можна
переходити від голосу до клавіатури й назад.

*Основний текст — англійський ([README.md](../../README.md)); переклад може відставати.*

**Розмова, а не диктування.** GPT-Live слухає, поки говорить: перебийте його, і він замовкне й вислухає вас; думайте вголос, і він може вставити коротке «угу». **Ви перестаєте платити за тишу:** OpenAI рахує голос похвилинно, тому після паузи, довжину якої ви задаєте в [Settings](#налаштування), лінія закривається й знову відкривається, коли ви заговорите, а розмова продовжується з того самого місця ([Оплата](#дбайливо-щодо-оплати)).

<p align="center"><img src="../assets/readme-demo.gif" alt="Розмова з сесією Claude Code через LiveBridge" width="100%"></p>

**Локально за задумом.** Жодної телеметрії та жодного власного сервера: LiveBridge — це міст на
вашому Mac між вашим власним codex і вашим власним Claude Code. Застосунок і мод спілкуються
через Unix-сокет, який може відкрити лише ваш користувач, а застосунок не слухає жодного
мережевого порту. Окрім того, що ці два інструменти й так надсилають (голосова лінія до OpenAI
через ваш codex, і лише поки вона відкрита, разом із тим, що ви набираєте в приєднаній сесії, та робота Claude до Anthropic через вашу сесію
Claude Code), застосунок сам виходить у мережу лише так: недовго живий codex, коли ви відкриваєте меню,
запитує в OpenAI дані про використання Codex, зокрема й за вимкненого дзвінка, та заради
[оновлень](#оновлення): автоматична
перевірка в GitHub, чи немає нового випуску (раз на день, а також під час запуску, доки
оголошений ним випуск не встановлено), яку можна вимкнути; та сама перевірка, коли ви натискаєте
**Check for update**; `gh auth status`, коли оголошено новий випуск; і завантаження, його
перевірка та оновлення мода, коли ви натискаєте **Install**. Що саме потрапляє до OpenAI,
перелічено в розділі [«Приватність»](#приватність), і там само названо запити застосунку до
GitHub; від чого це захищає, а від чого ні, сказано в [SECURITY.md](../../SECURITY.md).

> **Неофіційний проєкт.** Не пов'язаний з Anthropic чи OpenAI, не схвалений і не підтримуваний
> ними. Спирається на експериментальний realtime API codex, який може змінитися з будь-яким
> випуском codex.

## Швидкий старт

Потрібні macOS 14+ на Apple Silicon, Claude Code 2.1.301+ та
[codex](https://github.com/openai/codex) з виконаним входом (`codex login`) у план ChatGPT, у Codex
якого входить голос; щоб зібрати застосунок самостійно, ще й Xcode зі Swift 6.0+. Подробиці — в
розділі [«Вимоги»](#вимоги).

```sh
# 1. The mod, from this repository's marketplace
claude plugin marketplace add getLiveBridge/LiveBridge
claude plugin install livebridge@livebridge

# 2. The app, built from source, installed in /Applications and opened
git clone https://github.com/getLiveBridge/LiveBridge.git
cd livebridge
scripts/build-app.sh --release
```

3. У сесії Claude Code, з якою хочете розмовляти, введіть `/live`.
4. Натисніть **Start** у смузі над полем введення, дозвольте доступ до мікрофона й говоріть.

Не хочете збирати? У кожному [випуску](https://github.com/getLiveBridge/LiveBridge/releases/latest)
є застосунок у вигляді образу диска, який збирає й засвідчує GitHub Actions; як його перевірити
й відкрити, сказано в розділі [«З образу диска»](#з-образу-диска). Мод встановлюється однаково в
обох випадках.

Якщо `/live` не знайдено в сесії, що була відкрита вже раніше, відкрийте сесію заново
([чому](#відомі-обмеження)). Оновлення, дозволи, збереження дозволу на мікрофон між
перезбираннями та видалення описано в розділі [«Встановлення»](#встановлення).

## Вимоги

- macOS 14 або новіша на Apple Silicon.
- Claude Code 2.1.301 або новіший.
- [Codex CLI](https://github.com/openai/codex) (`codex`, перевірено з 0.166.0), встановлений через
  Homebrew (`brew install --cask codex`) або npm (`npm install -g @openai/codex`), у `PATH`,
  який ваша оболонка задає у вікні Terminal, з виконаним входом через `codex login` у план
  ChatGPT, у Codex якого входить голос (Plus, Pro, Business, Enterprise або Education, за
  [цінами Codex в OpenAI](https://learn.chatgpt.com/docs/pricing)). LiveBridge відмовляється працювати з codex, чий
  `codex features list` він не може прочитати, тож інша версія може не запуститися, доки
  LiveBridge не оновлять.
- Щоб зібрати застосунок: Xcode з інструментарієм Swift 6.0 або новішим. Перевірені версії
  наведено в [CONTRIBUTING.md](../../CONTRIBUTING.md#toolchain). Зібраний застосунок працює на macOS 14
  або новішій.

## Встановлення

Мод встановлюється з маркетплейсу цього репозиторію (команди зі [«Швидкого
старту»](#швидкий-старт)), який вказує на тег останнього випуску, тож ви встановлюєте мод саме
цього випуску. Застосунок в обох випадках опиняється в `/Applications`: з образу диска або
зібраний із вихідного коду. Починаючи з першого випуску після
0.4.2 образ диска підписано Developer ID LiveBridge і нотаризовано Apple; 0.4.2 і раніші підписано
ad hoc, і їх не нотаризовано, а збірку з вихідного коду не підписано Developer ID і не
нотаризовано.

### З образу диска

1. Завантажте
   [LiveBridge.dmg](https://github.com/getLiveBridge/LiveBridge/releases/latest/download/LiveBridge.dmg)
   з останнього випуску.
2. Перевірте його за допомогою [GitHub CLI](https://cli.github.com) у теці, куди збережено файл:

   ```sh
   gh attestation verify LiveBridge.dmg --repo getLiveBridge/LiveBridge \
     --signer-workflow getLiveBridge/LiveBridge/.github/workflows/release.yml \
     --source-ref refs/tags/vX.Y.Z --deny-self-hosted-runners
   ```

   де `vX.Y.Z` — тег випуску, як його названо на сторінці випуску. Перевірка проходить лише для
   образу, який [робочий процес випуску](../../.github/workflows/release.yml) цього репозиторію зібрав
   із цього тега на runner'і, що його надає GitHub, і який відтоді не змінився. На випуску після 0.4.2
   підпис Developer ID, який macOS перевіряє сама, каже, хто підписав образ, а ця перевірка каже,
   із чого його зібрано; на 0.4.2 і раніших, чий підпис ad hoc нікого не називає, ця перевірка —
   єдине свідчення походження образу. Того, що хтось переглянув код, це не доводить.
3. Відкрийте його й перетягніть LiveBridge до Applications.
4. Під час першого запуску випуск після 0.4.2 змушує macOS запитати, чи відкривати застосунок,
   завантажений з інтернету; натисніть **Open**. 0.4.2 і раніші заблоковані, доки ви не дозволите
   їх у Системних параметрах > Конфіденційність і безпека > **Open Anyway**.

### Через Homebrew

```sh
brew install --cask getlivebridge/tap/livebridge
```

Команда ставить той самий образ диска з [власного tap LiveBridge](https://github.com/getLiveBridge/homebrew-tap): це не офіційний cask
Homebrew. Homebrew може спершу попросити довіряти цьому tap, а macOS запитає під час першого запуску, як
описано вище. Далі застосунок оновлюється сам.

### З вихідного коду

`scripts/build-app.sh --release` збирає застосунок, встановлює його в `/Applications` (ваш
обліковий запис має мати право запису туди, як і обліковий запис адміністратора) і відкриває
його. Щоб перезібрати, запустіть команду ще раз. Збірка підписана ad hoc, тому після кожного
перезбирання macOS знову запитує доступ до мікрофона. Щоб зберегти дозвіл, один раз запустіть
`scripts/build-app.sh --make-signing-identity`: спершу скрипт запитає, потім створить
самопідписаний сертифікат для підпису коду у вашій в'язці ключів входу, і наступні
release-збірки підписуватимуться ним.

Маркетплейс закріплює мод за тегом останнього випуску, тож застосунок, зібраний з основної
гілки, працює з модом цього випуску. Щоб вони збігалися, зберіть тег випуску
(`git checkout vX.Y.Z`) або завантажте мод із робочої копії командою
`claude --plugin-dir plugin`.

Збірка з вихідного коду сама перевіряє оновлення, лише якщо ви ввімкнете це в Settings.
Встановлення оновлення замінює її образом випуску, який підписаний Developer ID
LiveBridge, а не вашим самопідписаним сертифікатом, тож macOS ще раз запитає доступ до
мікрофона; **Install** каже про це й спершу запитує.

### Оновлення

LiveBridge оновлює себе і свій мод, коли ви натискаєте **Install**, і ніколи сам по собі.
Оновлюється лише копія в `/Applications/LiveBridge.app`; будь-яка інша копія каже про це в
Settings.

- **Check for updates automatically** у Settings (типово ввімкнено, для збірки з вихідного коду
  вимкнено): раз на день застосунок запитує в GitHub, який випуск останній. Про новіший він
  повідомляє один раз, сповіщенням, чия кнопка **Install** його встановлює, а меню в рядку меню
  пропонує **Install LiveBridge X.Y.Z…**, доки його не встановлено, і заради цього пункту знову
  запитує GitHub під час кожного запуску. **Check for update** у Settings запитує одразу.
- Для **Install** потрібен [GitHub CLI](https://cli.github.com) з виконаним входом
  (`gh auth login`); без нього Install нічого не завантажує й дає посилання на сторінку випуску.
  Він завантажує образ випуску, перевіряє його тією самою командою `gh attestation verify`, що й
  вище, потім перевіряє застосунок усередині й нічого не встановлює, якщо не пройшла хоч одна
  перевірка. Він чекає, поки Claude ще зайнятий голосовим запитом, оновлює мод командами
  `claude plugin marketplace update livebridge` і `claude plugin update livebridge@livebridge`,
  зупиняє дзвінок, ставить новий застосунок на місце за один крок і відкриває його.
- Після цього Settings показує, з якої версії відбулося оновлення. Якщо мод оновити не вдалося,
  там будуть ці дві команди, щоб ви виконали їх самі. Сесії Claude Code, відкриті раніше,
  працюють зі старим модом, доки їх не перезапустити; Settings перелічує приєднані сесії, які
  ще на ньому.
- Завантаження оновлення не ставить атрибут карантину, тож macOS не мала б зупиняти перший
  запуск оновленого застосунку запитанням, як після першого завантаження; це випливає з коду й
  поки що не перевірено на ділі. Замість цього працюють перевірки вище
  ([SECURITY.md](../../SECURITY.md#what-an-update-installs)). Випуски після 0.4.2 підписані
  Developer ID LiveBridge, тож дозвіл на мікрофон має переходити від одного випуску до наступного;
  це випливає з того, як macOS прив'язує дозвіл, і поки що не перевірено на ділі.
  0.4.2 і раніші підписано ad hoc, тож перше оновлення з одного з них ще раз запитує мікрофон,
  під час першого **Start**.

Щоб оновитися вручну, введіть `/live off` в усіх сесіях (мод знову відкриває застосунок із
`/Applications`, щойно той перестає відповідати), закрийте LiveBridge, встановіть образ новішого
випуску, як описано вище, і виконайте дві команди `claude plugin`.

### Дозволи

Перший Start запитує в macOS доступ до мікрофона. Якщо у доступі відмовлено, дзвінок зупиняється
з повідомленням, а пункт **Open Microphone Settings** у меню застосунку в рядку меню відкриває
Privacy & Security > Microphone, де потрібно дозволити LiveBridge. macOS
запитує знову під час першого Start після першого оновлення з випуску, підписаного ad hoc, і
після кожного перезбирання з вихідного коду, підписаного ad hoc (див. вище). macOS
також може запитати, чи може LiveBridge знаходити пристрої у вашій локальній мережі. Голосовій
лінії потрібен і цей другий дозвіл; без нього дзвінок зупиниться з повідомленням, у якому
сказано, де його дати.

### Видалення

У копії з `/Applications` пункт меню **Feedback & Support ▸ Uninstall LiveBridge…** спершу
питає й переносить застосунок у Кошик; якщо не може, каже про це й більше нічого не змінює.
Потім відкритий дзвінок завершується і кожна сесія полишає LiveBridge, як від × у меню,
тож `/live` у ній вимикається, а не відкриває LiveBridge знову; LiveBridge прибирає вхід у
систему й дозвіл на мікрофон і закривається, а коли він закрився, його файли (перелічені
нижче) переходять у теку в Кошику, доки ви його не очистите. Мод Claude Code
лишається: команда, що його видаляє, `claude plugin uninstall livebridge@livebridge`, копіюється,
щоб ви запустили її в Терміналі. Сесія, яка тоді не була відкрита, може знову шукати
LiveBridge, коли відкриється; видалення мода це припиняє.

Встановлювали через Homebrew? `brew uninstall --cask getlivebridge/tap/livebridge` видаляє застосунок і запис Homebrew
про нього; кроки нижче й далі потрібні для файлів застосунку.

З клона репозиторію `scripts/build-app.sh --uninstall` видаляє `/Applications/LiveBridge.app`,
хоч як його було встановлено, його елемент входу та всі файли, що він зберігає, і виводить дві
команди, які залишає вам: `tccutil reset Microphone com.getlivebridge.livebridge` та
`claude plugin uninstall livebridge@livebridge`.

Без клона вимкніть **Open at login** у Settings LiveBridge, закрийте LiveBridge і виконайте ті
самі кроки в Terminal:

```sh
rm -rf /Applications/LiveBridge.app ~/Library/Application\ Support/LiveBridge \
  ~/Library/{Caches,WebKit}/com.getlivebridge.livebridge \
  ~/Library/HTTPStorages/com.getlivebridge.livebridge{,.binarycookies} \
  ~/Library/Preferences/com.getlivebridge.livebridge.plist
tccutil reset Microphone com.getlivebridge.livebridge
claude plugin uninstall livebridge@livebridge
```

Жоден із цих способів не видаляє копію з назвою `/Applications/.LiveBridge-update-….app`, яку
може залишити оновлення, перерване посеред встановлення. Застосунок видаляє такі копії під час
наступного запуску; після видалення застосунку видаліть її вручну, якщо вона є.

`claude plugin uninstall` може залишити знімок мода, `~/.claude/plugins/store/livebridge_*.json`: у
документації Claude Code про те, що видаляється, цього файлу немає, а перевірку не запускали. Якщо
він є, видаліть його вручну.

## Використання

### Команди

У сесії Claude Code, з якою хочете розмовляти:

| Команда | Що робить |
|---|---|
| `/live` | Приєднує сесію до LiveBridge під її заголовком і відкриває застосунок, якщо він не запущений. В уже приєднаній сесії повертає смугу й відповідає одним рядком: дзвінок, ціль, непрослухані результати, хвилини за сьогодні. |
| `/live off` | Відключає сесію від LiveBridge. |

Команда називається `/live`, а не `/voice`, бо `/voice` — це власний голосовий режим Claude Code.
Чи тримати набране в сесії поза голосом, поки дзвінок зупинено, визначає не команда: це одне
налаштування для всіх сесій у вікні [Settings](#налаштування) застосунку LiveBridge.

### Смуга й меню

Натисніть **Start** — у смузі над полем введення або в меню в рядку меню — і говоріть.

- **Start у смузі** робить її сесію ціллю й починає дзвінок; відкрита ним лінія отримує розмову
  сесії, а резюме завантажує й тоді, коли голосові бракувало б частини сесії (див. **Load context**
  нижче), але за ввімкненої **Pause sync** і після паузи лише якщо резюме ще немає
  ([подробиці](../../docs/architecture/overview.md#components)). З модом цієї версії резюме
  запитують під час Start і при зміні цілі протягом дзвінка, і лінія чекає на нього перед
  підключенням, не довше 10 секунд від запиту: сказане за цей час зберігається на Mac і йде до
  голосу, коли лінія відкриється. Stop або зміна цілі під час очікування відкидають збережене, як і
  перепідключення після зміни **Connect over TCP**, яке лишає знову відкритій лінії не більше
  останніх 2 секунд. Поки дзвінок іде з іншою сесією, смуга
  показує **Talk here**. Якщо в приєднаній сесії смуги немає, `/live` повертає її.
- **Меню в рядку меню** містить дзвінок, приєднані сесії (клацання робить сесію ціллю),
  **Load context**, **Conversation** цілі в тому вигляді, в якому його зберігає LiveBridge
  (з рядком **Task** на кожен запит, який голос передав Claude, і рядком **Loaded context** там, де було завантажено резюме),
  ліміти використання, хвилини, **Quick Settings** (пункти з позначкою для
  **Connect over TCP**, **Play sounds for requests and answers**, **Notify when a result is waiting**, **Pause sync while the call is stopped** та **Load a session's context on its first call**),
  **Settings…**, **Feedback & Support** (**Report a Bug…** відкриває форму звіту про помилку в
  репозиторії, **LiveBridge Website** відкриває getlivebridge.com, **Star LiveBridge on GitHub**
  відкриває сторінку репозиторію, далі **Debug Mode** і **Show Debug Files…**, перемикач і тека
  [режиму налагодження](#налаштування), і **Uninstall LiveBridge…** ([Видалення](#видалення))) та **Quit LiveBridge**. Quick Settings є й тоді, коли меню
  показує лише дзвінок. Під час дзвінка **Conversation** показує ваші слова й слова голосу в міру того,
  як їх розшифровує codex, тож ваші можуть з'явитися трохи пізніше, ніж ви їх сказали, а слова голосу
  трохи раніше, ніж ви їх почуєте. Коли репліку закінчено, її замінює остаточний текст. Зберігається
  лише остаточний текст: слова, які не дочекалися його до закриття лінії, зникають.
- **Mute** (поруч зі **Stop**, у смузі та в картці дзвінка в меню; **Unmute**, поки мікрофон
  вимкнено) звільняє ваш мікрофон, поки дзвінок триває: відповідь Claude, як і раніше, відкриває
  лінію й передається голосу, щоб той її вимовив. Смуга зберігає фазу й додає `· muted`; меню пише
  «Muted — line closed», поки лінію не відкрито. Mute не закриває лінію: відкрита лінія закривається
  після звичайної тиші, що відлічується від Mute, якщо ви говорили, і тоді, коли закрилася б без
  Mute, якщо лінія вже мовчала; вона оплачується як будь-яка тиша, тож Mute не заощаджує хвилини
  realtime. **Unmute** знову бере мікрофон, і якщо не виходить (доступ заборонено, зайнятий,
  відсутній), дзвінок завершується із зазначенням причини. **Stop** завершує дзвінок і Mute;
  наступний **Start** починається з увімкненим мікрофоном. Mute — не замок: будь-який процес,
  запущений від вашого імені, може його зняти ([SECURITY.md](../../SECURITY.md#who-can-drive-the-bridge)).
- **Load context** доступний, лише коли голосові бракує частини цілі: резюме немає, і **Pause sync** не дає наступній лінії його завантажити, хід не дійшов,
  запитання чи сповіщення про дозвіл не дійшли до застосунку, ходи йшли за вимкненого мода, рядків
  після резюме більше, ніж голос може прийняти (довга розмова це перевищує), сесію було призупинено
  і вона має резюме, або її мод не синхронізується. Інакше пункт називається **Context up to date** і недоступний, бо
  голос уже знає розмову. Якщо лінію не відкрито, наступна завантажить резюме і більше нічого не втрачено, він називається
  **Context loads with the line** і недоступний, бо наступна лінія запросить його сама. Поки резюме цілі в
  дорозі, хто б його не запросив, пункт показує **Loading context…** і недоступний, не довше 60 секунд, які дає на нього мод (у сесії зі старим модом він лишається **Load context**); резюме, що прийшло,
  на мить показує **Context loaded**, а порожня відповідь повертає **Load context**. Резюме не має дати, тому його може бути проігноровано, а пункт лишиться
  доступним ([BR-002](../../docs/bugs/BR-002.md)).
- **New conversation…** стирає розмову цілі та її завантажений контекст, а × біля сесії прибирає її
  й стирає її власну розмову; обидва пункти спершу запитують підтвердження. Голос починає наново від
  наступного відкриття лінії. Результати, яких він ще не промовив, залишаються й додаються знову; їх
  очищає лише **Stop**. Для запитань Claude, що чекають, правила інші
  ([подробиці](../../SECURITY.md#residual-risk-by-design)). Якщо ввімкнено **Load a session's context on its first call** або **Pause sync** вимкнено і сесію не
  призупинено, наступна лінія сама завантажує резюме тієї самої стенограми сесії, а в ній є текст
  розмови (застосунок і мод цієї версії прибирають вивід інструментів, міркування й нагадування,
  але не текст, що їх цитує, а старіші надсилають увесь запит); щоб цього уникнути, спершу виконайте `/clear` у сесії, потім натисніть **New
  conversation**. `/live` у прибраній сесії приєднує її знову.

### Налаштування

**Settings…** відкриває вікно налаштувань LiveBridge із чотирма вкладками на панелі інструментів.
**Quick Settings** у меню містить п'ять його перемикачів ([меню](#смуга-й-меню)): кожен пункт — це
саме налаштування, тож зміна в одному місці одразу видна в іншому, і він питає те саме, що
перемикач тут.
На вкладці **General** — сповіщення, вхід у систему, оновлення й режим налагодження:

- **Notify when a result is waiting** (типово ввімкнено): разом із сигналом про результат, що
  чекає, поки лінія закрита, сповіщення macOS називає сесію («Alpha has a new result — speak to
  hear it»), але ніколи не сам результат. Клацання по ньому відкриває меню в рядку меню.
- **Open at login** (типово вимкнено).
- **Updates**: поточна версія, **Check for update**, **Check for updates automatically** і що
  зробило останнє оновлення ([«Оновлення»](#оновлення)).
- **Debug mode** (типово вимкнено): під час дзвінка щосекунди пише рядок мережевих показників
  голосу (втрачені й відкинуті пакети, джитер, приховані семпли, чи йде лінія через TCP), по
  одному CSV на дзвінок, у `~/Library/Application Support/LiveBridge/debug/call-stats/`; ні звуку,
  ні розшифровки, ні назв сесій. Увімкнений під час дзвінка, він пише відкриту лінію з цієї миті;
  вимкнений, одразу зупиняється, а файли лишаються, доки ви їх не видалите. **Show Debug Files**
  відкриває теку. У меню це **Debug Mode** у **Feedback & Support**
  ([як читати показники](../../CONTRIBUTING.md#reading-debug-modes-numbers)).

На вкладці **Voice** — те, що ви чуєте під час дзвінка:

- **Voice**: один із realtime-голосів, які пропонує ваш codex (codex перелічує їх, коли
  відкривається ця вкладка), або **Codex default**. Звучить від наступного відкриття лінії.
- **Prompt** (типово порожній): ваші власні вказівки для голосу, наприклад «Speak with me in
  Spanish», до 2 000 символів. Їх додано після власних правил LiveBridge для голосу, які мають
  перевагу там, де вони розходяться, і діють від наступного відкриття лінії.
- **Play sounds for requests and answers** (типово ввімкнено): короткий звук на кожен запит, який голос
  передає Claude ([чому](#відомі-обмеження)), і на кожну відповідь, помилку чи запитання Claude, що
  надійшли на відкриту або відкривану лінію, коли ніхто не говорить. Сигнал результату, що чекає,
  лунає в будь-якому разі.

На вкладці **Line** — скільки лінія лишається відкритою в тиші та як вона під'єднується:

- **Silence before the line closes** (типово 20 секунд), **Wait for a first word on a line a result
  opened** (5 секунд) і **Sound without words before the line closes** (90 секунд): скільки кожен
  вид тиші тримає відкриту лінію, від 0 до 300 секунд. 0 вимикає тишу або звук без слів, а
  очікування першого слова при 0 триває стільки ж, скільки тиша. Коли всі три дорівнюють нулю, тиша
  ніколи не закриває лінію: вона залишається відкритою й увесь цей час оплачується
  ([Оплата](#дбайливо-щодо-оплати)), доки ви не натиснете Stop, не зміните ціль або OpenAI її не
  закриє. Коротка тиша закриває лінію посеред звичайних пауз, а кожне повторне відкриття займає
  кілька секунд, перш ніж голос відповість, тому Settings попереджає за значень від 1 до 9 секунд;
  так само й для звуку без слів, яким ваше мовлення вважається, доки його не розпізнано, і за
  значень від 1 до 3 секунд для першого слова, бо голос часто починає приблизно через 2 секунди
  після підключення лінії. Увімкнений таймер одразу починає відлік на тихій відкритій лінії; той,
  що вже йде, зберігає свій час.
- **Connect over TCP** (типово вимкнено): якщо голос рветься на поганому з'єднанні, увімкніть це.
  Лінія тоді віддає перевагу TCP-маршруту, який пропонує медіасервер (порт 443 у відповідях, які
  ми бачили), замість UDP і все ще може повернутися до UDP. На з'єднанні з втратами це може
  перетворити обриви на короткі паузи між фразами ([наскільки це перевірено](#відомі-обмеження)).
  Лінія, відкрита в момент перемикання, після вашого підтвердження одразу закривається і
  відкривається знову; те, що голос казав, обривається, а результат, на який чекала лінія, однаково
  прийде в нову.

На вкладці **Context** — як ваші сесії потрапляють до голосу:

- **Pause sync while the call is stopped** (типово вимкнено): за замовчуванням те, що ви набираєте в
  приєднаній сесії, і підсумкова відповідь Claude на це потрапляють у розмову цієї сесії з голосом,
  навіть коли дзвінок зупинено, і голос знає їх, коли відкриється наступна лінія. З Mac нічого не
  йде, доки не відкриється лінія. Якщо текст не має потрапити до OpenAI, увімкніть налаштування,
  вимкніть наступне, якщо резюме в сесії може ще не бути, натисніть Stop і лише тоді друкуйте: нічого з набраного, поки дзвінок зупинено, не записується, а
  сесію позначено як призупинену. Поки налаштування ввімкнено, жодна лінія сама не завантажує
  резюме, як і після паузи, крім сесії без резюме (наступне налаштування); в інших випадках
  це робить лише **Load context**. Таке резюме пишеться зі стенограми й несе те, що ви призупинили. Набране в ході, що виконує голосовий
  запит, провалює його відповідь: у ній нічого не записується й не промовляється. Налаштування
  нічого вже записаного не видаляє, а пізніші відповіді Claude можуть повторювати призупинений
  текст; що воно робить і чого не робить, сказано в
  [SECURITY.md](../../SECURITY.md#residual-risk-by-design).
- **Load a session's context on its first call** (типово ввімкнено; вимкнено, якщо під час оновлення було ввімкнено **Pause sync**):
  лінія, відкрита для сесії, резюме якої голос не має, запитує його, навіть якщо ввімкнено **Pause
  sync** або сесію призупинено, зокрема для старого чату і після **New conversation**. Таке резюме
  пишеться зі стенограми, тож несе те, що ви призупинили, і йде до OpenAI. Коли сесія вже має
  резюме, те, що йде далі, визначає пауза. Якщо налаштування вимкнено, під паузою резюме завантажує
  лише **Load context**.
- **Summary model** (типово Haiku 5.5, зокрема після оновлення; або Sonnet 5.5, Opus 5.5 чи **Custom…**):
  модель, яка пише резюме, що його голос отримує як контекст, завжди з низьким зусиллям, коштом
  вашого ліміту Claude. Якщо інша модель не впоралася, резюме пише Haiku 5.5, окрім випадку, коли тій моделі забракло часу. Рядок під
  налаштуванням каже, коли останнє резюме прийшло від Haiku 5.5 або ні від якої моделі, і чому.
  Сесія на моді, випущеному до цього налаштування, його не враховує й пише резюме власною моделлю.
  **Custom…** приймає id моделі й **Check and save**: приєднана сесія надсилає цій моделі один
  короткий запит ("Reply with OK.") коштом вашого ліміту Claude, і id зберігається, лише якщо
  модель відповіла; інакше причина з'являється біля поля, а попередній вибір лишається. Потрібна
  сесія на моді цієї версії, і перевірка говорить за Claude Code цієї сесії: інша сесія може
  відрізнятися, а збережений id більше не перевіряється.

### Що робить голос

- Сам відповідає на невимушену розмову та пояснення, а все, що потребує репозиторію чи сесії,
  передає далі: завдання, запитання про код, рішення, виправлення й зупинки.
- Перш ніж передати щось руйнівне або зовнішнє (видалити, запушити, опублікувати, надіслати,
  задеплоїти, сплатити), повторює запит і питає «так?». Це звичка, яку голосу велено
  дотримуватися, а не запобіжник; що є запобіжником, сказано в [SECURITY.md](../../SECURITY.md).
- Переказує результати одним-двома реченнями з назвою сесії. Блоки коду й таблиці залишаються в
  сесії, а розпізнані облікові дані приховуються.
- Повертається, коли Claude закінчив. Тримати лінію відкритою не потрібно: вона закривається, коли
  розмова стихає, а відповідь Claude на ваш запит знову відкриває її й передається голосу, щоб той
  її вимовив, тож поки Claude працює, можна відійти. Це стосується сесії, з якою ви говорите;
  результат з іншої сесії звучить сигналом і чекає ([як це оплачується](#дбайливо-щодо-оплати)).
  Якщо на знову відкритій лінії голос мовчить, відповідь теж звучить сигналом і чекає, тож вона не
  губиться. Запитання, яке Claude вам ставить, або запит дозволу, якого він чекає, відкриває лінію
  так само, але голос може його не вимовити: не покладайтеся на це, коли вас немає біля Mac ([відомі
  обмеження](#відомі-обмеження)).
- Коли Claude ставить запитання, воно передається голосу, щоб той поставив його вам, а ваша
  відповідь іде назад у ту саму сесію. Так само із запитанням, яке Claude ставить під час роботи
  (вікно з варіантами): голос отримує його, щоб розповісти про нього, пояснити варіанти своїми
  словами й обговорити їх із вами скільки завгодно, не звертаючись до Claude. Ваше рішення, варіант
  чи зустрічне запитання до Claude, стає відповіддю у вікні; відповісти з клавіатури теж можна.
  Робота, яку Claude завершує пізніше у фоні, передається голосу як оновлення.
- Коли Claude чекає на відповідь на запит дозволу, голос отримує сповіщення й може про це сказати,
  окрім випадку, [коли Claude Code керує організація](#відомі-обмеження). На запит ви відповідаєте в
  Claude Code; LiveBridge ніколи не відповідає за вас.
- Отримує те, що ви набираєте. Поки сесію приєднано, те, що ви в ній набираєте, і підсумкова
  відповідь Claude на кожен хід, що не був голосовим запитом, потрапляють у розмову цієї сесії з
  голосом як контекст: сигналу для них немає, і закритої лінії вони не відкривають
  ([обмеження](#відомі-обмеження)). Відкрита лінія отримує їх одразу, а лінія, відкрита пізніше,
  починається з них. Голосова відповідь, яку витіснив новіший запит, не промовляється, але
  зберігається й додається так само. Текст Claude посеред ходу не синхронізується, окрім того, що
  він написав просто перед запитанням чи запитом дозволу: це йде разом із ним; субагенти й вивід
  інструментів не синхронізуються. Запитання чи запит дозволу в цілі передається голосу, який би хід
  його не спричинив; в іншій сесії він іде, як ішов би результат звідти, а якщо хід не був голосовим
  запитом, лише записується. Хід, який пауза не пустила, цього не має. Коли запитання чи запит
  дозволу вирішено без голосу або хід закінчився без відповіді, голосу передається рядок про це
  ([які рядки](../../SECURITY.md#what-session-text-can-do)).

## Дбайливо щодо оплати

Realtime-сесія голосу коштує, поки відкрита, тому LiveBridge відкриває її лише поки хтось
говорить, поки ще може прийти відповідь Claude на ваш щойно переданий запит, або щоб озвучити
цю відповідь, запитання Claude чи те, що Claude чекає на ваш дозвіл:

- Поки дзвінок увімкнено й ніхто не говорить, мікрофон живить лише детектор голосу на вашому Mac.
  Звук нікуди не надсилається.
  Поки Mute увімкнено, LiveBridge не тримає мікрофон, і індикатор мікрофона macOS це показує.
- Коли ви починаєте говорити, лінія відкривається. Дві секунди до початку мовлення зберігаються
  й надсилаються першими, тож перші слова не губляться.
- Лінія закривається після відрізка тиші, а звук без слів (музика, телевізор) — після власного.
  [Settings](#налаштування) задає кожен; при 0 цей її не закриває.
- Коли голос передає запит Claude (handoff), лінія залишається відкритою до 2 хвилин після цієї
  передачі й оплачується як будь-яка відкрита лінія, а відповідь Claude передається голосу, щоб той
  її озвучив, щойно ніхто не говорить. Наступна передача починає ці 2 хвилини заново; обмін, що
  нічого не надсилає Claude, закривається після звичайної тиші.
- Відповідь Claude на запит, переданий сесії, з якою ви зараз говорите, запитання Claude в ній або
  запит дозволу, на який він чекає, що надходить після закриття лінії, знову відкриває лінію й
  передається голосу, щоб той її озвучив; це оплачується як будь-яка відкрита лінія. Усе інше, що
  надходить, коли лінія закрита (усе із сесії, з якої ви перемкнулися, пізніше оновлення), звучить
  сигналом і чекає: смуга та меню показують його як непрослухане, а голосу воно передається, коли ви
  заговорите наступного разу ([коли він вважається
  почутим](../../docs/architecture/overview.md#a-result-while-the-line-is-closed)).
- Кожна сесія Claude Code має власну розмову з голосом. Вона переноситься в наступну
  realtime-сесію, а також через Stop і Start, тож голос пам'ятає, що ви сказали хвилину тому.
  Нова ціль перемикає розмову: відкрита лінія закривається, а ваші наступні слова відкривають її
  з розмовою нової цілі.
- Меню показує хвилини, протягом яких лінія була відкрита, які застосунок рахує з моменту
  підключення голосу, тож ваш план може нарахувати трохи більше. OpenAI оцінює голос на комп'ютері
  похвилинно з бюджету використання Codex, а в її API те саме сімейство моделей тарифікує і тишу
  ([подробиці](../../docs/research/2026-11-04-gpt-live-billing.md),
  [ліміти](../../docs/research/2026-11-05-gpt-live-limits.md)); останнє слово за сторінкою використання
  вашого плану.
- Меню показує, яку частку ваших лімітів Codex і Claude використано: по рядку на кожен, у
  відсотках за кожне вікно, яке повідомляє план (до трьох у рядку, наприклад
  `7% of 5 h · 19% of week`), помаранчевим від 90 %; наведіть курсор на рядок, щоб побачити, коли
  вікна скидаються. Дані Codex зчитуються щоразу, коли відкривається меню, не частіше ніж раз на
  хвилину, короткоживучим codex; дані Claude надходять із приєднаної сесії, коли вона вже
  відповіла. Рядок, якому нічого показати, не виводиться, а рядок Codex каже `blocked`, коли codex
  повідомляє, що звичайне використання не дозволено. Останнє показання Codex видно одразу, а за
  кілька секунд його замінює нове, тож цифри можуть змінитися за відкритого меню; одразу після
  запуску рядок з'являється, коли надійде перше показання, а якщо читання не вдається, показання
  зникає за 15 хвилин. Який ліміт зупинить голос першим, не
  задокументовано ([подробиці](../../docs/research/2026-11-05-gpt-live-limits.md)).

## Приватність

LiveBridge не має телеметрії й не слухає жодного мережевого порту; мод спілкується із
застосунком через Unix-сокет у теці, яку може відкрити лише ваш користувач. До OpenAI через
realtime-сесію codex потрапляє таке:

- звук мікрофона, поки лінія відкрита: від двох секунд до початку вашого мовлення (або, для лінії,
  яку відкрила відповідь, запитання чи запит дозволу Claude, від її відкриття) й до закриття лінії
  (при Mute LiveBridge нічого не захоплює, тож звук не йде; сказане до натискання Mute на лінії, що
  вже підключалася, усе ж може піти);
- інструкції голосу: власні правила LiveBridge, а потім ваш **Prompt** із Settings, якщо ви його
  написали;
- нещодавня розмова сесії-цілі (до 64 останніх реплік і не більше, ніж приймає codex: 128 елементів
  і близько 8192 токенів разом із контекстом та відкритими завданнями), щоб продовжити її в новій
  realtime-сесії. У ній те, що ви набрали в цій сесії, і підсумкова відповідь Claude на кожен хід,
  що не був голосовим запитом, хоч би чим його було розпочато (ви його набрали, розклад, інший
  агент, фонове завдання), а також нотатки мода, ваші слова й слова голосу, тож набране в сесії йде до
  OpenAI, коли відкривається лінія з цією сесією. Поки лінія відкрита, кожна нова репліка цілі
  потрапляє в неї одразу. Синхронізовані репліки іншої сесії йдуть, лише коли лінія відкривається з
  нею як із ціллю; її результати, запитання й сповіщення про дозвіл потрапляють у відкриту лінію,
  чия б це сесія не була;
- запити сесії-цілі, що ще не закриті, у вигляді їхніх однорядкових описів;
- кожен результат, запитання, оновлення, сповіщення про дозвіл, набраний текст, відповідь на хід, що
  не був голосовим запитом, голосова відповідь, яку витіснив новіший запит, і нотатка мода — одним
  рядком не довшим за 2 000 символів, без блоків коду й таблиць (набраний текст, що складається лише
  з коду чи таблиці, замінюється реченням про те, що набрано код). Нотатки мода називають інструмент
  дозволеного чи вирішеного запиту дозволу й повідомляють, що запитання закрито або що хід
  закінчився без відповіді. Запитання, яке Claude ставить посеред ходу, і сповіщення про дозвіл,
  який запитав основний цикл Claude (не субагент), несуть й те, що Claude написав просто перед ними.
  Оновлення — це відповідь Claude в наступному ході, розпочатому сповіщенням фонового завдання,
  протягом 10 хвилин після голосового запиту й доки в сесії не почнеться будь-який інший хід;
- резюме контексту сесії-цілі — одним рядком не довшим за 1 500 символів. Воно зберігається під
  час завантаження й надсилається щоразу, коли лінія відкривається, поки ця сесія є ціллю, зокрема
  після Stop і Start та перезапуску застосунку. Підменю Conversation показує цей рядок точно в
  тому вигляді, в якому його надсилають;
- з кожним рядком вище — мітка його сесії: заголовок сесії Claude Code (до 80 символів) або, якщо
  його немає, назва теки сесії. У мітці нічого не приховується, і пауза її не торкається, тож
  заголовок, написаний із призупиненого тексту, іде з кожним рядком;
- WebRTC-пропозиція, яка перелічує локальні мережеві адреси Mac як кандидатів для з'єднання.

З увімкненим **Connect over TCP** звук і далі йде на медіасервер OpenAI і може йти через TCP
(порт 443 у відповідях, які ми бачили) замість UDP.

Результати, запитання, оновлення, резюме та рядки набраних ходів спершу проходять через фільтр відомих форм облікових
даних (приватні ключі, JWT, поширені API-токени, паролі в URL, поля на зразок `password=`). Це
список шаблонів, а не гарантія: усе інше, що ви набираєте, йде як набрано.

Тред codex, що несе голос, ефемерний і лише для читання, з вимкненими всіма функціями codex, крім
збереження вашого входу та способу використання вашого проксі, і з вимкненими всіма MCP-серверами;
він потрібен лише для розмови. Робота Claude потрапляє до Anthropic так, як і завжди у вашій сесії
Claude Code.

Коли ви відкриваєте меню, LiveBridge запускає короткоживучий codex, який питає в OpenAI під вашим
входом у ChatGPT, скільки вашого ліміту Codex використано (відсоток і час скидання кожного вікна).
Це не частіше ніж раз на хвилину й відбувається також за вимкненого дзвінка; звук і текст при цьому
не надсилаються. Дані Claude надходять до застосунку від мода через сокет і далі нікуди не йдуть;
обидва набори застосунок тримає лише в пам'яті.

Заради оновлень застосунок звертається до GitHub. Якщо ввімкнено **Check for updates
automatically**, раз на день (і під час кожного запуску, доки оголошений ним випуск не
встановлено) він без облікових даних запитує в API GitHub, який випуск останній; GitHub бачить
IP-адресу вашого Mac. **Check for update** у Settings надсилає той самий запит, коли ви його
натискаєте. Коли автоматична перевірка знаходить новіший випуск, застосунок запускає
`gh auth status`, щоб сказати, чи можна перевірити образ. Лише коли ви натискаєте **Install**,
він завантажує образ і запускає `gh attestation verify` та `claude plugin`, які звертаються до
GitHub, а `gh` ще й до Sigstore по корінь довіри, під вашими власними входами. Кожен запит
перелічено в [SECURITY.md](../../SECURITY.md#what-leaves-the-mac).

На вашому Mac застосунок зберігає свої налаштування, лічильник використання, час останньої перевірки
оновлень і версії, про які він повідомив, що зробило останнє оновлення та, для кожної з 20
останніх використаних сесій, її нещодавню розмову (до 64 реплік, зокрема набране вами в ній;
записується без дзвінка, якщо не ввімкнено **Pause sync**) і останній завантажений із неї рядок
контексту, у `~/Library/Application Support/LiveBridge`, у теці, яку може відкрити лише ваш користувач
([як вона зберігається](../../SECURITY.md#residual-risk-by-design)). Рядки сесії зникають, коли ви
натискаєте **New conversation**, поки вона є ціллю, або прибираєте її через ×. Сесія, що
відключилася, зберігає їх, доки їх не витіснять 20 пізніше використаних сесій; щоб стерти їх
раніше, знову введіть у ній `/live` і натисніть **New conversation**. Видалення застосунку
стирає все; Uninstall LiveBridge у меню переносить їх у Кошик, і вони зникають, коли ви
його очистите. Мод тримає власний знімок у сховищі плагінів Claude Code ([що в ньому](../../SECURITY.md#residual-risk-by-design)).
**Debug mode**, типово вимкнений, пише мережеві показники голосу під час дзвінка у файл у цій теці,
і нічого більше ([«Налаштування»](#налаштування)).

У [SECURITY.md](../../SECURITY.md) — модель загроз; коротко: усе, що чує ваш мікрофон, може стати
запитом, який Claude виконає в режимі дозволів самої сесії.

## Відомі обмеження

- **Connect over TCP** віддає перевагу TCP, але не змушує його, і під час дзвінка ніщо не показує, який
  транспорт обрала лінія, тож лінія, що повернулася до UDP, ще може рватися. Маршрут виміряно один
  раз, у налагоджувальній збірці, яка прибирала UDP-кандидатів (жодного втраченого пакета за 10
  хвилин); робочий спосіб, зниження їхнього пріоритету, один раз обрав TCP. Режим налагодження
  записує транспорт (`onTcp`) ([CONTRIBUTING.md](../../CONTRIBUTING.md#reading-debug-modes-numbers)).
- Голос іноді каже, що дивиться («On it», «Looking now»), але не передає запит, і до Claude нічого
  не доходить: приблизно один запит із п'яти з правилом у його першій редакції й 0 із 20 з нинішнім
  правилом, надто мало, щоб відрізнити від везіння ([BR-001](../../docs/bugs/BR-001.md)). Голос може й
  заявити про роботу, якої не робив, як-от «I'll take a look.», зокрема за репліками, які має лише
  як контекст ([ADR 0001 (n), (o)](../../docs/adr/0001-platform-findings.md)). Застосунок грає короткий
  звук, коли ставить запит у чергу для Claude, і це не той звук, що у відповіді; якщо голос каже,
  що дивиться, а цього звуку немає, повторіть запит. За словами застосунок не може відрізнити таку обіцянку від відповіді: голос
  говорить вашою мовою.
- Запитання Claude або запит дозволу, якого він чекає, лише передається голосу, і голос може його не
  вимовити; ніщо його не змушує. Тому не покладайтеся на те, що голос оголосить запит дозволу, коли
  вас немає біля Mac: Claude може чекати без жодного оголошення. Запит дозволу і далі чекає в Claude
  Code, і це єдиний контроль; голос контролем не є, а LiveBridge на нього ніколи не відповідає. У
  перевірках сповіщення про дозвіл із набраного ходу на відкритій лінії було вимовлено до відповіді
  з клавіатури в 0 із 3 запусків, це підрахунок, а не частка ([ADR 0001
  (n)](../../docs/adr/0001-platform-findings.md)). Закрита лінія відкривається заради них, лише якщо в
  розмові цілі є ваш хід; інакше застосунок подає сигнал, а за вимкненого дзвінка вони лише
  записуються.
- Що десктопний застосунок Claude повідомляє як джерело набраного тексту, не спостерігалося ([ADR
  0001 (m)](../../docs/adr/0001-platform-findings.md)). Мод записує набране як ваше, лише якщо його
  джерело `composer`. Якщо текст, набраний там, прийде з іншим джерелом, нічого набраного там не
  запишеться, пропуск не позначиться, меню скаже **Context up to date**, а пауза буде слабшою
  ([подробиці](../../SECURITY.md#what-session-text-can-do)).
- Результат, що надходить, поки лінія його чекає, передається голосу як текст для озвучення; у codex
  немає виклику, який змушує голос заговорити негайно, тож коли сказати, вирішує модель. Під час
  тестування голос озвучував його за кілька секунд. Якщо ні, результат залишається непрослуханим:
  він знову передається голосу з вашими наступними словами, або пролунає сигнал, коли лінія
  закриється.
- Коли відповідь Claude знову відкриває лінію, голос може промовчати: так було в 4 із 14 виміряних
  запусків, вибірка мала ([ADR 0001 (n)](../../docs/adr/0001-platform-findings.md)). Тоді лінія
  закривається, щойно скінчиться її очікування першого слова ([Settings](#налаштування)), а
  відповідь звучить сигналом і чекає, як описано нижче. Коли голос заговорював, він починав приблизно
  в межах 2 секунд після підключення; голос, який почав би пізніше цього очікування, обривається.
- Коли ваші наступні слова знову відкривають лінію, голос іноді відповідає лише на них і не
  озвучує результат, що чекає. Результат не губиться: він далі чекає, звучить сигналом і
  надсилає сповіщення, коли лінія закривається, і знову передається голосу, коли лінія
  відкриється наступного разу.
- На ліміті використання вашого плану ChatGPT голос зупиняється, доки ліміт не скинеться. Меню й
  смуга кажуть про це фразою codex із часом скидання, якщо codex його називає, а дзвінок
  завершується, щоб мовлення не відкривало ліній, які дають збій. Claude Code далі працює,
  відповіді далі чекають, а Start пробує ще раз. Ліміт застосунок розпізнає лише за формулюванням
  codex або кодом помилки сервісу: більше про нього нічого не повідомляє
  ([подробиці](../../docs/research/2026-11-05-gpt-live-limits.md)). Відмова, яку він не розпізнає,
  наприклад лінія, що обірвалася без пояснення причини («The voice session closed
  (transport_closed).»), залишає дзвінок увімкненим, і ваші наступні слова пробують знову;
  натисніть **Stop** до скидання ліміту.
- Промпт, набраний не в композері (повідомлення хоста, розклад, інший агент і, мабуть, Remote
  Control), не записується в розмову голосу як ваші слова, хоча відповідь Claude на нього
  записується, і під паузою не відхиляє хід, що триває
  ([SECURITY.md](../../SECURITY.md#what-session-text-can-do) каже, які промпти вважаються вашими).
- Якщо провайдер Claude Code (Bedrock, Vertex або Foundry) не пропонує модель, вибрану в
  **Summary model**, або організація її не дозволяє, ця модель не впорується й резюме пише
  Haiku 5.5; якщо немає й Haiku 5.5, голос не отримує резюме, про що каже Settings. До цього
  налаштування резюме писала власна модель сесії, яка працює скрізь, де працює сесія. Те, що
  закріплений id розпізнається в цих провайдерів, узято з документації Claude Code і не перевірялося.
- Сесія, що лишилася на моді з версій до цієї, доки не перезапуститься, не синхронізується: вона
  завантажує резюме, як сесія з пропущеними ходами, і жодна пауза не відхиляє її реплік ([що ще
  відрізняється](../../CHANGELOG.md)).
- Сесії Claude Code, що була відкрита ще до завантаження мода, може знадобитися повторне
  відкриття, перш ніж у ній запрацює `/live`.
- У десктопному застосунку Claude `/live`, введена в сесії, процес Claude Code якої ще не
  запущений (нова сесія або щойно відкрита заново), може показати «/live isn't a command here.»
  Команда все одно виконується. Десктопний застосунок бере список команд такої сесії з перевірки,
  яку запускає з вимкненими хуками, тому код мода, що оголошує `/live`, там не виконується; коли
  сесія запущена, застосунок бере список у самої сесії. З боку мода це не виправити: статичний
  файл команди потрапив би до списку як `/livebridge:live`, а не `/live`, і з вимкненими хуками
  надіслав би свій текст моделі замість того, щоб запустити мод.
- Чи озвучила відповідь результат, що чекає, визначається за її словами, за списком поширених слів
  лише англійської та російської мов
  ([правило](../../docs/architecture/overview.md#a-result-while-the-line-is-closed)). Іншою мовою
  результат може зарахуватися почутим, коли голос лише згадав його.
- Там, де Claude Code керує організація, ніщо в LiveBridge не повідомить вас, що чекає запит
  дозволу. Вбудований захист Claude Code завантажується на комп'ютері з керованими налаштуваннями
  та в сесії, де виконано вхід із планом Team або Enterprise, і там хуки дозволів мода не
  виконуються. Запит і далі з'являється в Claude Code і чекає на вас, але голос про нього нічого
  не каже, а меню показує, що Claude працює, тож зазирніть у Claude Code, якщо відповідь
  затримується. `/plugin` називає ці хуки, а свіжі версії Claude Code ще й виводять рядок про те,
  що хук пропущено. Запитання Claude і далі доходять до голосу. Хуки
  [виміряно](../../docs/adr/0001-platform-findings.md) у контейнері Linux; те, що роблять голос і рядок
  меню, випливає з коду, справжню лінію не запускали. Випадок Team та Enterprise описано за
  документацією Claude Code.
- З `allowManagedHooksOnly`, `allowManagedModsOnly` або `disableAllHooks` у керованих
  налаштуваннях мод не завантажується і `/live` не працює. Адміністратор може [встановити мод як
  власний мод
  організації](https://code.claude.com/docs/en/plugins/mods/admin#install-your-organizations-mods)
  із теки на кожному комп'ютері: тоді хуки дозволів виконуються, зокрема з першими двома
  налаштуваннями ([виміряно](../../docs/adr/0001-platform-findings.md)). За документацією Claude Code,
  увімкнути копію з маркетплейса в керованих налаштуваннях недостатньо.

## Плани та де потрібна допомога

Сьогодні LiveBridge — це один застосунок для Mac, один виконавець (Claude Code) і один постачальник
голосу (codex на вході в ChatGPT). Ці три частини стикуються вузькими швами, і кожен із напрямів
нижче відкритий для учасників. Завдання щодо них мають мітку
[help wanted](https://github.com/getLiveBridge/LiveBridge/issues?q=is%3Aissue+is%3Aopen+label%3A%22help+wanted%22);
з яких файлів почати, сказано в [CONTRIBUTING.md](../../CONTRIBUTING.md#where-to-start).

- **Windows і Linux.** Застосунок у рядку меню, його аудіосторінка та сервер сокета прив'язані до
  macOS; протокол між модом і застосунком та сам мод переносні. Перенесення починається із
  застосунку для нової платформи, який говорить тим самим протоколом.
- **Інші агенти як виконавці**, як-от Codex CLI, Hermes Agent або Gemini CLI: кожному потрібен
  власний адаптер, який говорить тим самим протоколом, що й мод Claude Code.
- **Інші постачальники голосу**, як-от OpenAI Realtime API з вашим власним API-ключем або Gemini
  Live API від Google: кожен був би ще однією реалізацією realtime-протоколу застосунку.
