# Mute: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Dispatch by wave: a wave's tasks share no file and may run in parallel.

**Goal:** a Mute that releases the owner's microphone while the call goes on, so Claude's answers
still open the line and are said; Unmute takes the microphone again.

**Architecture:** two new call actions (`mute`, `unmute`) on the existing `POST /v1/call`, an
`isMuted` field in the status, a flag in `CallMachine` that ignores the owner's speech and emits
two new audio effects, and `LB.mute()`/`LB.unmute()` in the audio page that stop and re-attach the
microphone input. The band and the menu's call card draw the second button.

**Tech stack:** Swift 6 / SwiftPM (BridgeCore, Swift Testing), the audio page in JavaScript
(`node --test` in `app/Tests/AudioJSTests`), the mod in TypeScript (`claude plugin test`).

**Spec:** `docs/specs/2026-11-05-mute-design.md`

## Global Constraints

- A wire change touches `app/Sources/BridgeCore/Wire/Wire.swift`, `plugin/hooks/wire.ts` and
  `wire/fixtures/` together. A failing test before each change; one behaviour per test.
- LiveBridge never answers a Claude Code permission prompt; Mute changes nothing there.
- Docs change with the behaviour; README and its translations, shared by Tasks 2 and 4, are
  updated once in Task 5 so Wave 2's tasks share no file.
- Never add `Co-Authored-By: Claude` or any Claude attribution. `scripts/check.sh` exits 0 before
  each commit.

## Review Focus

- Unmute while the track-ended handler races (a device change during mute) must not leave two
  inputs attached (Task 3, `unmuteAttachesOneInput`).
- Mute while the owner is speaking on a live line must end the speech (`isSoundOn` false) so the
  line closes by the 20 s rule, not the 90 s noise cap (Task 2).
- A result arriving while muted and listening must still open the line (Task 2).
- Stop while muted, then Start, must start unmuted with the microphone captured (Task 2, Task 3).
- An older mod (no `isMuted` in its status type) must keep working (Task 4).
