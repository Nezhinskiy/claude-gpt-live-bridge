# Mute: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Dispatch by wave: the waves follow the Consumes/Produces edges, a wave's tasks share no file and no build, and each wave builds and passes `scripts/check.sh` on its own.

**Goal:** a Mute that releases the owner's microphone while the call goes on, so Claude's answers
still open the line and are said; Unmute takes the microphone again.

**Architecture:** two new call actions (`mute`, `unmute`) on the existing `POST /v1/call`, an
`isMuted` field in the status, a flag in `CallMachine` that ignores the owner's speech and emits
two new audio effects, and in the audio page one generation token, in a new pure module
`microphone.js`, that every microphone acquisition checks. The band and the menu's call card
draw the second button.

**Tech stack:** Swift 6 / SwiftPM (BridgeCore, Swift Testing), the audio page in JavaScript
(`node --test` in `app/Tests/AudioJSTests`), the mod in TypeScript (`claude plugin test`).

**Spec:** `docs/specs/2026-11-05-mute-design.md`. **Review:** `docs/reviews/2026-11-05-mute-review.md`
on branch `review/mute`; what was taken is under [Review rulings](#review-rulings).

## Global Constraints

- A wire change touches `app/Sources/BridgeCore/Wire/Wire.swift`, `plugin/hooks/wire.ts` and
  `wire/fixtures/` together. A failing test before each change; one behaviour per test.
- LiveBridge never answers a Claude Code permission prompt; Mute changes nothing there.
- Docs: the PR is "the change" that AGENTS.md's rule ("fix the docs in the same change as the
  code") means. The code tasks land without their docs and Task 5 brings every doc in the same PR,
  so no two parallel tasks share README, its translations or SECURITY.md.
- Never add `Co-Authored-By: Claude` or any Claude attribution. `scripts/check.sh` exits 0 before
  each commit. Commands below run from the repository root.

## Review Focus

- An acquisition pending when Mute lands (Start's, Unmute's, a device change's) must end with no
  live track and no input (Task 3, the three `…LeavesNoLiveCapture` tests).
- Mute while the owner is speaking on a live line must end the speech, so the line closes by the
  20 s rule, not the 90 s noise cap, and a result held meanwhile still gets its grace (Task 2).
- A result arriving while muted and listening must still open the line (Task 2).
- Stop while muted, then Start, must start unmuted with the microphone captured (Task 2
  `stopWhileMutedThenStartListensUnmuted`, Task 3 `releaseClearsTheMute`).
- A newer mod against an older app (no `isMuted`) draws no Mute; an older mod keeps working
  (Task 4).

**Interfaces — consumes** nothing. **Produces:** `LB.mute()` (synchronous) and `LB.unmute()`
(a promise that resolves once the microphone is back or its failure was posted).

`microphone.js` is pure: no `window`, `navigator` or `AudioContext`. It exports:

- `createMicrophone({ acquire, connect, disconnect, watchDevices, onLost })`, returning
  `{ attach(): Promise<boolean>, mute(): void, unmute(): Promise<boolean>, deviceChanged(): void,
  release(): void, readonly muted: boolean }`.
  - `acquire(isCurrent)` resolves to a capture `{ node, stop(), onEnded(handler | null) }`, or to
    null when `isCurrent()` turned false between its own awaits (it then holds nothing).
  - `connect(node)` and `disconnect(node)` wire a capture's node to the processor.
  - `watchDevices(handler | null)` installs or removes the device-change handler.
  - `onLost(error)` hears a failed re-acquisition after a device change.
- `microphoneFailure(error)`: `{ type: 'microphoneDenied' }` for `NotAllowedError`, otherwise
  `{ type: 'audioFailed', reason }` with the sentence for `NotFoundError`, `MicTimeoutError` or
  any other error (busy). The three sentences move here from `say`.

The token, which the tests do not fully determine:

- `attach()` returns false at once while muted, without acquiring. Otherwise it reads the token
  and awaits `acquire`, passing `isCurrent`, a check that the token is unchanged. After that
  await:
  - if the token moved, it stops the capture (if any) and returns false;
  - if `acquire` rejected and the token moved, it returns false; if the token did not move, it
    rethrows.
  - Otherwise it unhooks, stops and disconnects the previous capture, hooks
    `onEnded(deviceChanged)` on the new one, connects it, calls `watchDevices(deviceChanged)` and
    returns true.
- `mute()` bumps the token first, then sets `muted`. It unhooks, stops and disconnects the
  current capture and calls `watchDevices(null)`. A second call changes nothing.
- `unmute()` resolves true while unmuted, without acquiring. Otherwise it clears `muted` and
  returns `attach()`.
- `deviceChanged()` runs `attach()` and passes a rejection to `onLost`.
- `release()` bumps the token, clears `muted`, and stops what `mute()` stops.

`audio.js` wires the module:

- `acquire` is today's two paths, against the context it started with. `fake` is kept in module
  state beside `ctx`: `listen(fake)` sets it, `stop()` clears it.
- `watchDevices` is a no-op for the fake microphone, as `listen` installs none today (:142).
- `listen` attaches through the module. It returns early only when `ctx` changed. A false from a
  muted microphone still resumes the context, so a result can open a line.
- `failMicrophone(error)` runs `stop()`, then posts `microphoneFailure(error)`. `listen`'s catch
  (when still current) and `LB.unmute()` share it. `onLost` keeps posting `say.lost`.
- `LB.mute()` runs the module's `mute()`. With a context, it gives the voice detector a fresh
  start (the setup `listen` does at :123). With no peer (`pc` null), it also resets the line's
  audio. Then it posts one `level` 0. Before `listen`, it only records the mute.
- `LB.unmute()` is `mic.unmute().catch(failMicrophone)`.
- `process` while muted fills the output with silence and, when `sending`, still plays the queue.
  It skips the detector, the pre-roll and the `level` posts.
- `stop()` calls `release()` in place of its own handler and track handling.
- The local gain `const mute` (:128) is renamed `silent`.

`preroll.js` gains `createLineAudio({ sampleRate })`. It moves in the `holding` flag, the
pre-roll and the catch-up queue that `process`, `hold` and `closePeer` use today, with
`write(frame)`, `hold(keep)`, `pull()`, `clear()` (what `closePeer` empties) and `reset()` (clear,
and the pre-roll emptied).

## Review rulings

The owner ruled on the review (`docs/reviews/2026-11-05-mute-review.md` on branch `review/mute`)
before execution.

- **Taken, with the review's fix:**
  - CR-1 to CR-15;
  - SI-1 to SI-4, SI-6 and SI-7 (SI-7: the Unmute latency is accepted and stated in the spec);
  - SE-1 to SE-3, and SE-5 and SE-6, which CR-15 and CR-4 fold in.
- **SE-4, in part.** The manual checks are taken: headset changes, and Mute during an
  acquisition. The native deny is not taken, because the fix is not sound as given. WebKit's
  media-permission handling may reuse the page's earlier grant without asking the delegate, and
  then the deny never runs. It may also remember a denial for the page, and then one stray
  request denied while muted would fail the next Unmute and Start as "denied" until the page
  reloads. Neither can be verified in tests here. A native backstop that does not go through the
  delegate (watching `WKWebView`'s microphone capture state while muted) is left for a separate
  decision.
- **SI-5, not taken:** the explicit pairs stay (`CallEvent.mute`/`.unmute`,
  `CallEffect.muteMicrophone`/`.unmuteMicrophone`, `AudioSide.muteMicrophone()`/
  `unmuteMicrophone()`, `BandActions.mute`/`unmute`). Each matches one wire action and one test
  row. A parameterised form saves about five declarations but makes every call site carry a
  boolean, and the review itself rates the current form acceptable.
