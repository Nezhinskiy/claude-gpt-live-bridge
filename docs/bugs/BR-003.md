- **Found:** 2026-11-12, on a real call.
- **Where:** `plugin/hooks/context.ts`, `summarize()`; `plugin/hooks/register.tsx`, `writeAndPost`,
  `deliverContext` and `contextAsked`; the test `nothingToForkIsNoFailure` in
  `plugin/tests/context.test.tsx`, which pins the behaviour.

With **Load a session's context on its first call** on, the owner resumed a Claude Code session
that had a long history, typed `/live` and pressed Start. No context reached the voice, **Load
context** stayed enabled, and neither the session, the menu nor the voice said anything.

**What was observed** (times UTC, from the session's transcript and the app's `continuity.json`):

- 16:31:21 Claude Code resumed the session (`SessionStart:resume`).
- 16:31:22 `/live` joined it. The session had turns, so the join said `missed`
  (`register.tsx`, `if (byOwner && (await hasTurns($))) noteGap()`), which also drops any kept
  summary.
- 16:31:29 the line opened and the app asked for a summary: `summaryAsk {isStale: false}`.
- No context ever arrived: the conversation kept `outOfSync: "missed"`, which `setContext` clears.
- The transcript holds no model request until 16:32:31, when the owner's spoken request started
  the first turn of the resumed process.

**Why.** `summarize()` writes the summary with `$.model.fork`, which repeats the main thread's last
request. The engine's contract for `ModelForkResult` (Claude Code 2.1.321) says it answers
`nothing-to-fork`, making no request, "until a turn has run to its end, … again after a `/clear`,
or a resume that starts the conversation afresh". At 16:31:29 the resumed process had run no turn.
`summarize()` turns `nothing-to-fork` into `''`, `writeAndPost` turns `''` into `'empty'` without
posting, and `contextAsked` logs `NO_SUMMARY` only for `'failed'`. The mod reads "nothing to fork"
as "a session with nothing to summarise", which it is only when the session has no turns, a case
`deliverContext` already returns for before it forks (`hasTurns`).

So the app's ask is never answered, the line runs without the session's context, and nothing says
so. The same holds for a press of Load context before the process's first turn ends, and for the
first call of any session Claude Code has just started.

**Run** (`claude plugin test plugin` at 82bccb0, the fake world's default `turns: 1`):

```text
(pass) nothingToForkIsNoFailure [105.28ms]
 194 pass
 0 fail
```

The test asserts that, in a joined session with a turn, a fork that answers `nothing-to-fork`
posts no context and logs no "could not summarise" line: the silence, as intended when it was
written.

**Ruled out:** the fork running long on the session's own model (Opus 5.5 High over a long
context) and passing the mod's 60 s `CONTEXT_TIMEOUT_MS`. That ends in `'failed'`, which logs
`NO_SUMMARY` as a dim line in the transcript (`$.ui.log` defaults to the transcript); the owner
saw none, and no request was made.

**Suggested fix:** a hypothesis, for the owner to choose.

1. **Small, in the mod.** In a session with turns, `nothing-to-fork` is a failure, not an empty
   session: post an empty summary, which the app's `context` route already takes as the end of the
   ask (`Bridge.context`, a blank summary yields `announceContext` and sets nothing), log a line
   that says why ("nothing to summarise from until this session's next turn ends"), and send the
   summary when the session's next turn ends if the ask still needs it. What must not change: a
   session with no turns stays silent, and no wire change is needed.
2. **The spec's route.** `docs/specs/2026-11-09-summary-model-design.md` writes the summary with
   `$.model.complete` over the transcript on a chosen model, which needs no snapshot of the main
   thread, so it works right after a resume, and its `ContextBody.failures` lets the menu say why a
   summary did not come. That replaces `fork` and closes this entry, but it is the larger change
   and is still proposed.

The first can ship before the second and is dropped by it.

**What this evidence does not establish:** the fork's answer was not observed directly, since forks
are not in the session's transcript; it is inferred from the engine's documented contract and
the timing above. No resumed session was reproduced end to end.
