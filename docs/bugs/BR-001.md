- **Found:** 2026-11-04
- **Where:** `app/Sources/BridgeCore/Codex/VoicePrompt.swift`, the paragraph of `VoicePrompt.text`
  against promising a look without a handoff: added in 20649ff, reworded in 6fd3b26, trimmed in
  54ecab1. It is the only thing that makes the voice hand off. `RealtimeSession.handoff(_:)` in
  `app/Sources/BridgeCore/Codex/RealtimeSession.swift` is the only path a request takes to Claude.

The owner asks for something, the voice answers "Looking now" or "I'll take a look", and no
`handoff_request` item arrives. Nothing reaches the Claude Code session, the line waits for a
result that will never come, and the owner is told nothing. The Conversation submenu shows no
"Task" line for that request. [ADR 0001](../adr/0001-platform-findings.md) (b) measured it
before and after the rule.

A probe on 2026-11-04 saw it again (`codex-cli 0.166.0`). It ran a debug build with `--fake-mic`
saying "Please list the files in this folder" and the smoke test's fake session. Each run had a
fresh home, so it had no owner prompt, `autoContext` off and no seeded conversation. Of the 10
lines that opened, 3 promised a look and handed nothing off. Each failed run's `continuity.json`
holds the owner's line and the voice's, and no `handoff` line:

```text
run 3   owner : Please list the files in this folder
        voice : On it — I'll check that folder.
run 8   owner : Please list the files in this folder
        voice : Looking now.
run 9   owner : Please list the files in this folder
        voice : I'll take a look.
```

The model did not delegate; codex and the app dropped nothing. codex traces every frame the
realtime websocket receives in `~/.codex/logs_2.sqlite`, under the target
`codex_api::realtime_websocket::wire`; it keeps about 6 MB of rows per process and prunes older
rows. In the three failed runs the record is unbroken from the request to the line's close. It
holds the owner's turn and the voice's turn, with no `delegation.created` frame and no
`thread/realtime/itemAdded`. Run 3:

```text
{"type":"turn.done","turn":{...,"end_ms":3600,"role":"user","start_ms":1200,"transcript":"Please list the files in this folder"}}
{"type":"turn.created","turn":{...,"end_ms":3600,"role":"assistant","start_ms":3400,"transcript":" On it"}}
{"type":"turn.done","turn":{...,"end_ms":6800,"role":"assistant","start_ms":3400,"transcript":" On it — I'll check that folder."}}
app-server request: thread/realtime/stop
```

Nothing else that reaches the model changed since 20649ff. The only other prompt change is
8ca5b24's `[ASKING]` paragraph. The realtime model was the default in both measurements, and the
realtime options are the same.

**Measurement.** Same setup as the probe; one line per run, closed 6 s after the voice answered.
A and B alternated; C ran later the same evening. Each run was read from codex's wire log right
after it ended.

| Rule | Lines | `delegation.created` | Promised a look, no handoff |
|---|---|---|---|
| A, 20649ff | 20 | 17 | 3 ("Sure, I'll take a look.", "On it—I'll pull up that folder's contents now.", "On it, checking that folder now.") |
| B, 6fd3b26: the owner's framing in full | 20 | 18 | 2 ("On it—I'll check.", "Looking now.") |
| C, 54ecab1: B cut to its one new rule | 20 | 20 | 0 |

- With A the rate is about one in five (3 of 20 here, 3 of 10 in the probe). (b)'s 0 of 5 was luck.
- B is chance against A. C's 0 of 20 against A's 3 of 20 is not significant either (Fisher's
  exact test, one-sided, p ≈ 0.12); it bounds C's rate below about 14% at 95%.
- The voice starting 200 ms before the owner's turn ended is common in delegated runs too, so it
  is not the cause.
- `scripts/smoke.sh` passed with B and with C: no handoff for small talk.
- The 60 runs kept a line open about 825 s, roughly $0.70.

**Suggested fix:** a hypothesis. A model instruction is not a control, so the owner must be able
to notice a missing handoff. Matching the voice's words cannot do that in every language. The
signal has to come from the handoff event itself.

**Mitigation, in place.** When a handoff is queued for a session, in any phase of the line, the
app plays a short sound (`CallEffect.confirmHandoff`; e0fb2a1, 434e8df). Settings can turn it off
(3270008). It makes the failure audible; it does not prevent it, so the entry stays open.

- Whether the microphone picks the sound up is not settled.
  - Automated runs with `say` through the speakers could not test it: echo cancellation removed
    most of that speech too.
  - One run with the owner's own voice queued the request, and the voice's acknowledgement was
    whole. The app recorded no second owner turn.
  - If the sound does leak, play it through the audio page, in the same output path as the voice.
- Others do the same. [openai-agents-python#541](https://github.com/openai/openai-agents-python/issues/541)
  asks the same question and got only prompt advice. [duck_talk](https://github.com/dhuynh95/duck_talk/blob/main/docs/sound-design.md),
  Gemini Live in front of Claude Code, plays a tap on the tool call.
- A language-independent control others report: a second, small text model reads each reply
  against the handoffs and runs a missed one. It costs a model call per reply.
- codex's `flushTranscriptTailOnSessionEnd` is no recovery path here. At `rust-v0.166.0`, the
  session's end records the talk since the last handoff in the codex thread's history
  (`realtime_conversation/transcript_tail.rs`: "without inference"). It runs no model and sends
  no handoff. The pattern stays open to the app: at the line's close, send Claude that talk and
  let it decide. That costs a Claude turn after most lines.

What must not change with it: the voice still answers from what it already has without a handoff,
hands each request off once (the `handoff_id` de-duplication), and asks "yes?" before anything
destructive or outward; the app still never answers a Claude Code permission prompt.

**What this evidence does not establish:** three things a later plan must not assume.
- **That C fixed it.** 20 runs cannot tell a lower rate from luck.
- **Whether the rate depends on the request, the language or the voice.** Every run used one
  English request in a synthetic voice.
- **Whether the sound is enough for the owner to notice.**
