# Review of PR 37: the plan's usage limit ends the call and says so

- Pull request: [getLiveBridge/LiveBridge#37](https://github.com/getLiveBridge/LiveBridge/pull/37),
  `fix/voice-usage-limit` → `dev`, two commits (`2421733`, `b2be7a9`). Reviewed at `b2be7a9`
  against `0243a42`.
- Run with `superpowers:requesting-code-review` (one independent reviewer), `simplify` (its four
  angles, report only) and `security-review`. Findings only; nothing was fixed and the PR branch
  was not touched.
- Verdict: **merge after fixes.** 0 Critical, 5 Important, 13 Minor. The security pass found no
  vulnerability. The core works: a limit at open, or carried by codex's `closed`, ends the call,
  keeps what waits, ends codex, and Start recovers. The fixes are about what happens *around* that
  ending.

## How this was checked

- codex was read at tag `rust-v0.166.0` (`error.rs`, `api_bridge.rs`, `realtime_conversation.rs`,
  `truncate.rs`), and issues #55531 and #55494 were read in full. The installed CLI is 0.166.0.
- CI is green at `b2be7a9` (`check`, CodeQL). The independent reviewer also ran the 5 touched
  suites (123 tests) and the 4 new JS tests: all pass.
- **Proven** below means a throwaway test ran against a scratch copy of `app/`, with `FakeAudio`
  gated where a race needed it; no test was added to the repo. The tests are kept in the session
  group's notes folder, `pr37-review-proofs/`: `ReproTests.swift` (r1 to r5, each asserts what the
  owner should get and fails today), `ReviewProofTests.swift` (the `proof…` names, each asserts
  today's behaviour and passes) and `FakeAudio-gates.diff`.
- **Forced** means the interleaving was forced with those gates: the code can do it, but the
  timing was not seen in a real call. No voice was used; `scripts/smoke.sh` was not run.
- The mutation results in R-5 are the independent reviewer's and were not re-run.

## Is it elegant? Is anything redundant?

**Mostly, with one real weakness: `off` now means two things.** Before this PR `off` meant
"nothing is kept": `Stop` resets everything. `pause` makes a second kind of `off` that keeps
`unheard`, but nothing else knows the difference. R-2, R-3 and R-4 are the same mistake three
times: the delivery path, the route and the menu each still assume the old `off`. A small named
state answers all three at once (see *Design*).

**Redundant: the teardown.** The machine decides the call is over, then `Bridge` infers that from
`phase` at three sites (`endIfStopped`), and `.lineError` hand-writes a fourth copy of the close
sequence. It is that hand-written sequence, closing *before* telling the machine, that opens the
races in R-6. Moving this into the machine's effects removes code and fixes them together (S-1).

**Not redundant:** `Problem.isUsageLimit` is a thin delegate, but `CallMachine` holds a `Problem`
and `sentence` lives on `CodexProblem`, so both are earned. `peer === pc` and the `isLineOpen` guard
both do real work as the code stands. No dead code: the `plan` hint is still reached by
`usage_not_included`.

### Design: a pause the machine knows about

Two options, for the implementer to weigh:

1. **A flag** (smallest): `CallMachine.isPaused`, set by `pause`, cleared by `.start` and `.stop`.
   `(.off, .deliver) where isPaused` appends and chimes (R-2), `Bridge` keeps a question's route
   while one waits (R-3), and the copy reads the flag (R-4). No wire change.
2. **A `paused` `CallPhase`** (clearest): the same, with the band and menu able to say "Voice
   paused". It is a wire change (`Wire.swift`, `plugin/hooks/wire.ts`, `wire/fixtures/`), and an
   older mod must tolerate the new value.

Recommended: the flag, unless the band should name the pause.

## Findings

Line numbers are at `b2be7a9`. Severity is the effect on the owner.

### Important

**R-1. The app says the plan's limit is reached on a signal that does not show it.**
`CodexLaunch.swift:40-42` with `:54`; pinned by `CodexLaunchTests.swift:155`; also
`CHANGELOG.md`, `docs/architecture/overview.md:455`.

- `usage_check_failed` is a `service_unavailable_error` (research note §2): the service could not
  *verify* usage. In #55494 `account/rateLimits/read` gave `ordinaryUsageAllowed: true` and 0 % of
  the week used, on the top plan; #55531 read `ordinaryUsageAllowed=true` two minutes after the
  error. #55531 adds that this describes ordinary usage, "not an independently verified voice
  allowance", so a voice-only limit is not ruled out. The point is narrower: nothing shows a limit
  was reached, and the owner is told as fact that one was.
- Proven (r6), the owner reads: "Your ChatGPT plan's usage limit is reached, so the voice is
  paused. Claude Code keeps working. Unable to verify usage availability.
  (usage_check_failed)". In both reports it did not clear by waiting, so they wait for a reset
  that may not come, on a fault that may have nothing to do with their plan. The doc comment on
  `Problem.isUsageLimit` ("until it resets") claims the same.
- The research note asks only that `usage_check_failed` "shows its own words"; it is not in the
  note's list of limits. So this goes beyond the requirement.
- Secondary: `last status: 429` is codex's fallback for *any* 429 body (`api_bridge.rs:249`), so
  "reached" is unproven there too. The note did ask to treat it as a limit, so only the wording is
  at issue.
- **Resolution:** keep ending the call on all of them; ending is right, as a new line fails the
  same way. Split the one predicate in two: "this ends the call" and "the limit is known to be
  spent" (codex's four sentences). The others get their own sentence, for example "ChatGPT could
  not confirm your plan's usage, so the voice is paused. Claude Code keeps working." plus the
  service's words.

**R-2. An answer that arrives after the limit is not kept: no chime, no count.**
`CallMachine.swift:159`, reached through `pause` (`:297`); `CHANGELOG.md`.

- `(.off, _)` drops `.deliver`. Proven (r5, `proofAnswerAfterLimitIsNotKept`): a request is
  handed off, the limit ends the call, and the answer arrives: `unheard=0`, `chimes=0`. It is
  recorded in the conversation and seeds the next line, but the voice is not given it to say.
- This is the likely shape of the failure, not a corner: the sentence promises "Claude Code keeps
  working", so requests in flight will finish while the call is off. The research note's
  recommendation says "chime and keep answers waiting".
- The independent reviewer set this aside as "the same as Stop". This review does not: at Stop
  the owner chose to leave, and here the owner is waiting for the answer and nobody pressed
  anything. The owner may rule otherwise.
- **Resolution:** keep lines that arrive during the pause (*Design*). If it stays as it is, the
  changelog's "keeps what waits" should say it covers only lines that had already arrived.

**R-3. A kept question loses its route, so the owner's answer goes to the wrong session.**
`Bridge.swift:226`.

- `endIfStopped` copies Stop's `questionRoute = nil`, but Stop also drops the line and `pause`
  keeps it. That breaks the rule at `Bridge.swift:522`: a question the call keeps routes the next
  handoff.
- Proven (r4, `proofKeptQuestionLosesItsRoute`): Beta, not the target, asks; the limit hits; after
  Start the voice can say "[QUESTION] Beta: Which branch?"; the owner's reply is queued as
  `[TASK] Alpha: …`. A spoken instruction reaches the wrong Claude session, possibly another
  project, and Beta keeps waiting.
- **Resolution:** clear the route only when no kept line from that session is `.question` or
  `.asking`, and add that row. The doc comment on `endIfStopped` changes with it.

**R-4. "Speak to hear" while the call is off.** `MenuContent.swift:95-98`,
`ResultNotice.swift:19-24`, reached through `pause`'s `.chime` (`CallMachine.swift:301`) and
`Bridge.swift:329-335`.

- `unheard > 0` while off is new with this PR, and the copy assumes a call. Proven
  (`proofOffSaysSpeakToHear`): the card shows Off with "1 unheard — speak to hear", and the
  notification says "… has a new result — speak to hear it." The microphone is released, so
  speaking does nothing. The band and `/live status` give no instruction, so they are correct.
- The sentence does not say what to do either: "paused" gives no hint that the next step is Start.
- **Resolution:** while off, say "start and speak to hear" in the card, and pass the phase to
  `ResultNotice.waiting` for the same change. End the limit's sentence with what to press, or let
  the reset time carry it where codex gave one.

**R-5. Changed lines with no test that fails without them, against AGENTS.md.** Mutations that
survive all 123 tests:

| Removed or changed | Line | Why it matters |
| --- | --- | --- |
| `endIfStopped` after `.closed` | `Bridge.swift:451` | The mid-line path: without it codex stays running after a limit. |
| `questionRoute = nil` | `Bridge.swift:226` | Goes with R-3. |
| clearing `isHeld` in `pause` | `CallMachine.swift:298` | A held line would stay held after Start. |
| the `isLineOpen` guard | `Bridge.swift:213` | |
| `connecting?.cancel()` in `.lineError` | `Bridge.swift:214` | The test covers only `.live`. |
| `realtime?.close()` in `.lineError` | `Bridge.swift:217` | Redundant: `shutdown` closes (S-1). |

`estimatedTokens` and `endIfStopped` after `connectFailed` are caught, so
`aRussianSeedStaysUnderCodexsLimit` is real. Nothing tests `peer === pc`, as `audio.js` is not
unit-tested; that is the existing pattern.

- **Resolution:** at least a Bridge test for `.closed(limit)`; `proofClosedWithALimitEndsCodex`
  passes on the PR and catches the first row. Add a `.connecting` case for `.lineError`, and R-3's
  row. S-1 removes the rows it makes moot.

### Minor

**R-6. The limit can be lost to a close at the same moment.** `Bridge.swift:210-219`.

- Three orders, all Forced, all ending with the old bug: the call stays on and each word opens a
  failing line.
  - r1 (`proofClosedDuringLineErrorLosesTheLimit`): `.lineError` closes the peer *before* it tells
    the machine, unlike Stop. A `closed(transport_closed)` landing during `await audio.closePeer()`
    moves the machine to `listening`, so the later `.remoteClosed` does nothing. A silence timer
    firing in that gap does the same (read, not run).
  - r2: a `closed` that wins outright. `.lineError` is dropped by `isLineOpen`, and the page's
    `peer === pc` already drops it after `closePeer`.
  - `proofLineErrorWaitsBehindTheSpeechThatOpensTheLine`: `App.swift:170` consumes page events one
    at a time and `.speechStarted` stays suspended until `openLine` ends (`Bridge.swift:284`,
    `:147`). An `error` before `session.started` waits out the 10 s timeout, the owner sees "did
    not open in time", and the limit is dropped. Only result-opened lines reach the `.connecting`
    branch in time.
- Minor, not Important, on the one measurement there is: #55531 has the data channel about 0.91 s
  ahead of the sideband reset, and `session.started` first. One report on one setup, so not a
  guarantee.
- **Resolution:** S-1 fixes r1. For r2, let a limit act in `listening` as well as on an open line;
  ending the call is right whichever line said it. For the third, deliver `.lineError` outside the
  serial stream.

**R-7. `.connected`'s effects can erase the limit's sentence.** `CallMachine.swift:192`,
`Bridge.swift:278`.

- Proven (r3, Forced): `send` runs its effects with awaits between them, and the machine has
  already moved on. With the limit arriving during `flushPreroll`: `call=off`, problem set, then the
  list reaches `.problem(nil)` and the sentence is gone. The owner sees Off with no reason.
- Only reachable on a line a result opened (see R-6's serial stream), and the error must land
  within the effects' milliseconds; #55531 has it about 1.4 s after the channel opens.
- **Resolution:** `.problem(nil)` first in that list, as `.start` already does, or skip the rest of
  an effect list when the machine has left the phase it was computed for.

**R-8. `lineError` drops a code beside an empty message.** `events.js:13`. Ran it:
`{"message":"","code":"usage_check_failed"}` returns `""`, so nothing is posted. `??` does not fall
through on an empty string. **Resolution:** `message || code || null`, and the case in
`events.test.mjs`.

**R-9. The data channel recognises one code, by wording meant for codex.** `CodexLaunch.swift:54`,
`events.js:13`.

- The regex is tuned to codex's `Display` text, but the page carries the service's own words, so
  a real exhaustion in another wording (for example `type: usage_limit_reached`, or
  `insufficient_quota` with "You exceeded your current quota") is dropped silently, and nothing
  logs it. Whether the service sends those here is not documented, so this is untested exposure,
  not an observed miss.
- A sentence's `(code)` suffix is built in `events.js` only for a regex to read it back.
- **Resolution:** S-3.

**R-10. A control character in the sentence blanks the band.** `band.tsx:86`. The security pass
ran it on engine 2.1.312: the engine refuses the tree on such a character, so every joined session
loses its status row and Start/Stop, not just the error row. It needs a hostile author, codex's
text has the same exposure already, and the owner keeps the menu. Not a vulnerability.
**Resolution:** strip C0 and C1 in `Problem.sentence`, one place for both paths.

**R-11. `usage_not_included` still retries forever.** `CodexLaunch.swift:54`;
`otherErrorsAreNoUsageLimit` pins it. A plan without voice opens a failing line per word, the bug
this PR fixes for limits; codex groups it with limits (`error.rs:505-507`). It is by design here
and tested, so this is a question, not a defect. **Resolution:** the owner decides; the predicate
split in R-1 makes it a one-word change.

**R-12. ADR 0001 (o) does not exist.** Cited at `Continuity.swift:76`, `ContinuityTests.swift:7`;
the ADR ends at (n). "codex counts bytes" has no home. **Resolution:** add (o), citing
`truncate.rs:94-97` and `realtime_conversation.rs:1584-1598`.

**R-13. Doc drift.**

- `docs/architecture/overview.md:452` still says "any realtime error … back to `listening`", one
  bullet above the exception.
- `CHANGELOG.md`: "its reset time" is not true of the data channel, which carries none.
- Research note §2 heading says "implemented", but `contains` replaced "starts", and
  `usage_check_failed` became a limit.
- ADR 0001 (k) says `closed` follows the error, and the research note and `handle_start` say no
  `closed` is sent at open. The code handles both, but two homes disagree.
- `README.md` known limitations: nothing is false now, so optional, but the wording-based match
  and its English dependence are what an owner on a later codex would want to know.

**R-14. Test wording.**

- `CodexLaunchTests.swift:153` says "codex's own words", but "You hit your spend cap. Ask your
  admin." and "Your workspace is out of credits. Ask your admin." are not its sentences (compare
  `error.rs:758-776`). Use the literals, so the test fails when the strings would.
- `usageLimitsAreRecognisedInCodexsWords` asserts five things per message, against "one behaviour,
  one test"; split recognising from the sentence.
- `aRussianSeedStaysUnderCodexsLimit`: `bytes` holds tokens, and the test sits above the suite's
  `let` properties.

**R-15. A comment claims a change that did not happen.** `audio.js:213`, "kept for the line's whole
life": the handler was never removed. The PR adds one parse to it. Research note §2 item 5 ("reads
the data channel only until `session.started`") needs the same reading: it ignored later events.
**Resolution:** say what the line does: it reports `error` events.

**S-1. One way to end a call, in the machine.** `Bridge.swift:210-219`, `:224-228`, `:392`, `:451`;
`CallMachine.swift:297-302`.

- `pause` returns `[.closeRealtime, .stopLocalVAD, .endCodex, .problem(reason)]` in the machine's
  own order, and `end(with:)` gains `.endCodex`. `.lineError` shrinks to a guard and one `send`;
  `endIfStopped` and its three calls go. That moves the machine first, which closes R-6's r1, and
  `.failed` stops being the one path that leaves `questionRoute` set.
- Caution: on the `connectFailed` path `.closeRealtime` would cancel the connecting task from
  inside itself, and `stopListening` then runs in a cancelled task. If `callAsyncJavaScript` honours
  that, the microphone stays on. Verify it, or skip the cancel on that path.

**S-2. `pause` repeats `end(with:)`.** `CallMachine.swift:297-302`. `self = CallMachine()` is
`end(with:)` plus a carry-over; `unheard.map { Unheard(line: $0.line) }` is a third copy (`:238`,
`:286`, `:298`); the chime rule repeats `hangUp`. A new step in `end` would silently miss `pause`.
**Resolution:** a `withoutHolds` helper, and build `pause` on `end(with:)`.

**S-3. The page's error is dressed as codex's.** `Bridge.swift:212`, `events.js:13`.
`Problem.codex(.realtimeError(…))` holds text codex never sent, only to reuse `sentence` and the
regex. **Resolution:** `lineError` returns `{code, message}`, `AudioEvent.lineError` carries both,
and the code decides, not the prose. A `Problem` case of its own then carries R-1's second
sentence, and R-9 and R-8 fall away.

## The five questions

1. **`isUsageLimit`.** No real codex string is missed: every `UsageLimitReachedError` branch
   (`error.rs:733-840`), `QuotaExceeded` and `RetryLimit` with a request id match, in both
   apostrophes, and `lowercased()` leaves `’` alone. `contains` beats the note's "starts", as
   `Stream(…)` wraps messages. `TransportError::RetryLimit` reports 500, so it does not match. A
   false match needs a 4xx or 5xx body that echoes a phrase; the worst case is one ended call that
   shows the words, and Start recovers. The real false *claims* are R-1's. Not read:
   `parse_terminal_provider_error`, which runs first on some paths (`api_bridge.rs:114`).
2. **`pause`.** The reset is complete by construction, and the mute reset agrees with the page
   (`LB.stop` releases). `pending`, the status count and a later Start are right: the line is left
   out of the seed and added at `connected` (`Continuity.swift:67`, `CallMachine.swift:192`).
   `withdraw` and `rename` work while off, and the HTTP handler's `changed()` publishes the count.
   The chime is `NSSound`, so `.stopLocalVAD` before it does not silence it. Wrong: R-2, R-3, R-4.
3. **`endIfStopped` and `.lineError`.** The cancel comes before any await, so an attempt still
   opening cannot reach `.connected`. A cancelled `.connectFailed` does not swallow a limit: what
   cancels it is Stop, a target change, a withdraw, or `closed`, which carries `lastError`. `retire`
   is idempotent (`Bridge.swift:420`), and a late `closed` after `close()` or `retire` is ignored
   (`RealtimeSession.swift:204,292`, `Bridge.swift:428`). `shutdown` does not wait on the event
   loop that may be calling it, so no deadlock. The meter matches Stop. A Start during teardown on
   the `catch` path is dropped for a few milliseconds, as `connecting` is still set; the owner
   presses again. Wrong: R-6, R-7.
4. **`audio.js`.** `onmessage` was already never removed, so the PR adds one `JSON.parse` per event
   and no leak; the closure holds `peer`, which outlives it anyway. Those events are small control
   messages, not audio, which goes as RTP, so although the parse shares the main thread with the
   `ScriptProcessor` pump there is no measurable latency; an `includes('"error"')` test first is
   not worth it. `peer === pc` is the right guard: `pc` and `channel` are set and cleared together,
   and `channel` is read synchronously in the Promise executor. **Trust:** the text reaches the UI
   only after matching the regex. `Label(problem)` takes a `String` variable, so it is not parsed
   as Markdown, the band's `Text` is plain, nothing logs it, and it reaches neither a prompt nor
   the voice. There is no length cap (out of the security review's scope). R-8, R-10.
5. **`estimatedTokens`.** The comment is true: `approx_token_count` is `(len + 3) / 4` over bytes
   (`truncate.rs:94-97`), checked per item and in total (`realtime_conversation.rs:1584-1598`). No
   test or budget relied on the old count: ASCII is unchanged, and `Bridge.maxContext` (1,500
   characters) stays far under the budget. Already true before this PR and not made worse: notes
   are uncapped in total (`Continuity.swift:64-65`), so enough open tasks could still pass the
   limit. Lines are capped in characters, each.

## The three passes

**`superpowers:requesting-code-review`.** With fixes. Its Important items are R-1, R-3, R-4 and
R-5; this review adds R-2. Its Minor items are R-6, R-12, R-13 and R-14.

**`simplify` (report only).**

- Reuse: S-1, S-2. Simplification: S-2, and the regex as a list of phrases, which is taste and not
  raised. Altitude: S-1, S-3; it also proposes a `.limitReached` event instead of branching inside
  `handle`, which is reasonable but not needed if the *Design* flag is taken.
- Efficiency: nothing worth a change (question 4). Two `lowercased()` per non-limit error is
  noise.
- Altitude's other conclusion stands: English wording is the only signal on codex's path, so one
  place is the right depth, and it will rot silently with codex's copy. That is why the literal
  strings in R-14 matter, and why the follow-up in the research note remains.

**`security-review`.** No HIGH or MEDIUM finding. Range reviewed: `0243a42..b2be7a9`; the skill's
own file list was against `main`.

- Remote text is plain in every sink. The service can end a call by its wording, but it can
  already close the line, and the failure is safe: microphone stopped, peer closed, codex retired,
  no permission prompt touched.
- The seed change can only send less. Non-string JSON is dropped at `AudioSide.swift:27`, or
  coerced harmlessly.
- Considered and rejected: `/live status` (confidence 4; the one sink not tested, and it needs the
  service as author); carriage return or bidi text in the band (confidence 3; plain-text spoofing
  at most); a stale `lineError` closing a newer line (confidence 3; availability only). R-10 is
  availability, not security.

## Set aside

- Stale silence or result timers after a quick Start: the same as Stop.
- `event.data.includes` on a binary frame: already there, and the service sends text.
- A second `lineError`: idempotent.
- `applyAnswer` pending up to 10 s after `closePeer`: the same as Stop.
- A kept line from a session removed while paused: the same as `listening` today.
- No sound at the limit when nothing waits: not a regression.
- The research note's codex line numbers: cite main, differ slightly from the tag, and the code
  they point at matches.
